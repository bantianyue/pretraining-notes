跳过 DRAM 层：vLLM 智能体 KV 缓存直放 NVMe（中文精读）

  • 原文：Skip the DRAM Tier: MoRI UMBP Runs the Agentic KV Cache on NVMe（vLLM Blog，2026-11-23）
  • 收藏：2026-11-23，4⭐
  • 主题：KV 缓存、推理优化、vLLM、NVMe、分层存储
  • 一句话要点：智能体多轮会话反复发长前缀，KV 命中决定吞吐；vLLM 把 KV 池直接放 NVMe，同等 1.8 TB 下吞吐与 DRAM 池相差不到 1%，NVMe 买到的是留存时间。

为什么值得读

智能体服务的流量大头是多轮会话反复发送的长前缀，AgentX 回放真实 Claude Code 会话的中位一轮是 14.2 万输入 token，96% 以上是服务器已经见过的前缀。命中只处理小增量，缺失重算整个前缀。KV 池是 GPU 内存之外的第二层，但 DRAM 也会满：Kimi-K3 每小时写 2.3–4.6 TB KV，1.8 TB DRAM 池（约 7.6 万美元）只留住最近 23–47 分钟。这篇的结论是跳过 DRAM 层、池子直放 NVMe，并且给出了完整的实测证据与成本账。

核心结论

  • 同等容量，同等吞吐。1.8 TB NVMe 池与 DRAM 池在 48、70、96 会话下吞吐相差 1% 以内，命中率相差不超过 0.08%。另一对机器上重复三档负载，NVMe 反超 0.4%、0.5%、0.9%。长提示词语料（kvlab，70 会话）NVMe 落后 0.6%（8,110 对 8,162 tok/s/GPU）。
  • 没有 DRAM 层。池子 1.8 TB 全在 NVMe 上，DRAM 只做 64 GB 写缓冲与 16 GiB 读暂存，总共约 80 GB。70 会话下去掉写缓冲也没代价（反而 +3.5%），96 会话下写缓冲重要（去掉则吞吐 -6.7%）。
  • 吞吐跟着命中率走。42 次运行里命中率单独解释吞吐方差的 96%（R²=0.96），每多 1% 命中约值 1,280 tok/s/GPU。同等容量、同等淘汰规则下，两池留下的 KV 几乎一样。
  • 异步加载藏住慢读取。vLLM 的 KV 连接器 API 允许异步加载，请求在 prefill 队列里等的时间里完成加载。64 会话下一次加载 DRAM 0.80 秒、NVMe 0.85 秒，在 prefill 开始前约 2 秒完成。单请求无队列时 NVMe 命中比 DRAM 多 0.4 秒（0.84 秒对 0.45 秒），缺失则多约 7 秒。
  • NVMe 买的是留存。DRAM 按持有量计价（每 TB 约 4.2 万美元），NVMe 按写入量计价（每写 1 TB 约 0.36 美元盘寿命）。Kimi-K3 一天写 83 TB，存一天 KV 的 NVMe 池约 5.9 万美元，DRAM 池约 350 万美元。留存低于约 24 分钟时 DRAM 更便宜。
  • 留存崩了吞吐就崩。只用 GPU 内存时命中率从 32 会话的 90% 跌到 48 会话的 41%，吞吐跌 80%；4.6 TB NVMe 池在每一档负载下命中率保持 92.7%–95.8%，70 会话下 8,813 tok/s/GPU，是 1.0 TB DRAM 池的 5.1 倍。

三处改动

  1. 小分段文件。UMBP 只追加写，淘汰一个块不释放空间，要删整个文件才回来。默认 4 GiB 文件删文件时连带丢掉仍在用的 KV；改到 256 MiB，命中率 94.45%→95.65%，TTFT p90 从 63.0 秒降到 21.3 秒，吞吐 +15.6%，NVMe 从比 DRAM 低 12.8% 变成高 0.8%。
  2. touch。GPU 内存自己服务最热的前缀，池子看不到它们被读、会先淘汰它们。vLLM 连接器把每次 GPU 前缀命中上报给池子，标成最近用过。DRAM + NVMe 池上吞吐 +2.1%/+3.9%，TTFT p99 从 70–77 秒降到 35–43 秒。
  3. 多留检查点。Kimi-K3 的 KDA 状态只存在于检查点处，默认每段提示词末尾一个检查点，分叉处找不到就重算。每 7,168 token 加一个检查点，命中率 91.4%→95.6%，吞吐 +33%（5,113→6,791 tok/s/GPU）。检查点占 NVMe 写入一半以上，丢掉已被替代的检查点可省 53% 写入（2.26→1.05 TB/小时），代价是吞吐 -1.0%、TTFT p99 从 38 秒升到 62 秒。

成本账（挂牌价，非实测）

  • DDR5 约 42 美元/GB，企业级 SSD 约 666 美元/TB（2026-11-13 挂牌价中位数）。
  • NVMe 池五年成本取盘买价与写入耗掉的盘寿命中大的一个，再加约 3,400 美元 DRAM。1.8 TB NVMe 池与存一天的 83 TB 池子成本一样，约 5.9 万美元。
  • 一天留存代替 31 分钟，少缺失约 1% 提示词 token，约值 10% 吞吐（串了两个拟合模型，留存模型只在 36 分钟到一小时之间验证过）。

局限

  • 池子服务大部分 token 的重读场景还没比较（同等容量运行里池子最多服务 16% 的提示词 token；DeepSeek-V4-Pro 的池子在 64 会话以上服务 64%–86%，对比只做到 64 会话）。
  • 轻负载没有队列可藏，NVMe 加载多出来的时间直接加到 TTFT 上。
  • 多数结果只跑了一次；最大 NVMe 池 4.6 TB，跨两个节点；存一天的池子是算出来的。
  • 每 token KV 更多的稠密模型（无 MLA）要多存数倍，盘带宽也要多出同样倍数。
  • 部分改动还在合入上游的路上。

可复用的点

  • 按写入量给 NVMe 池定大小：跑峰值负载读每小时写盘多少 TB，容量 = 写入速率 × 留存时间；盘满时每天每盘写入次数 = 24 ÷ 留存小时数。
  • 命中率是第一性指标：池子设计先看同等容量下留下的 KV 是否一样（淘汰规则），再看加载路径；介质本身的延迟差可以被排队藏住。
  • 检查点是写入的大头：混合模型的 KDA 检查点占 NVMe 写入一半以上，丢弃已被替代的检查点是省盘寿命最直接的手段。
  • DeepSeek-V4.1-Flash 的有界重放：窗口只有 128 token 时不留窗口检查点、命中时从最后 128 token 重建，比每 2K token 留一个检查点快 2.2 倍。
