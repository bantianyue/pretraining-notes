Thinking Machines Inkling 2 Small：594B MoE 全程 NVFP4 训练 — 中文精读

原文：Inkling 2 Small（Thinking Machines 官方博客，2026-11-05 发表） 收藏：2026-11-09，星级 5⭐（核心必读：全程 NVFP4 预训练 + 联合 RL 的完整配方） 主题：训练核心流程 / MoE 架构 / 低精度量化（NVFP4）/ 强化学习 / 并行策略（训练） 模型：Inkling 2 Small（Thinking Machines 第二代模型，594B 总参数 / 17B 激活的多模态 MoE，支持图像输入与可变推理深度）

一句话要点

594B 总参数、17B 激活的 MoE，全程原生 NVFP4 在 GB300 NVL72 上 68 小时跑完 8.4T token 预训练，再经 1075 步、1700 万次以上 rollout、9 天的联合 RL（总算力超 4×10²³ FLOPs、2048 张 GPU）；FrontierCode 25.4%、DeepSWE 72.1%、SWEBench Pro Hard 86.3%、AA-Briefcase 1527 分，DesignArena 网站榜 1340 分居开源权重首位；先经 Tinker 封闭权重提供，安全测试完成后下周以 Apache 2.0 开源权重。

模型总览

  • 594B 总参数、每 token 激活 17B 的 MoE；Artificial Analysis 智能指数 30.6（v5.0）。
  • 原生支持图像输入（292M 参数视觉编码器，见下），不支持音频；可变推理深度。
  • 评测条件：努力程度 0.99（xhigh）、温度 1.0，单条轨迹上限 1M token（上一代 Inkling Small 为 256K）。

预训练四阶段：全程原生 NVFP4

  • H1：8.4T token，68 小时，GB300 NVL72 机架。混合自然语言、代码与图像数据，全程原生 NVFP4——Blackwell GPU 架构引入的 4 位浮点格式。NVFP4 训练方法的更多细节将在后续文章里分享。
  • H2：3.8T token更高质量、更新的数据（模型此前没见过），上下文 512K。
  • H3：约 320B token推理与 Agent 轨迹，上下文 1M，辅以重放的预训练数据。
  • H4：约 34B token只保留最高质量数据的 Agent 轨迹。
  • H3 与 H4 的混合数据大多是早期模型采样的轨迹（包括 Kimi K3 与团队自己的模型），按正确性与对齐过滤。
  • 压缩效率（内部代码截止 2026 年 6 月、每字节比特数，越低越好）：预训练版 0.2030、微调后版 0.2080，明显优于 GLM-5.3（0.2358）、DeepSeek V4 Pro Base（0.2335）等开源权重模型。

联合 RL：1075 步的系统栈

  • 1075 步、1700 万次以上 rollout、9 天，总算力超过 4×10²³ FLOPs，2048 张 GPU。
  • RL 基础设施部署 NVFP4 MoE 训练与采样：采样时预填充、草稿与验证全程跑在 CUDA graph 上；训练器复用预训练栈，高专家并行、EPLB 与 CUDA graph 提升 GPU 效率。
  • 长程 Agent 负载用粘性路由与 DRAM KV 缓存卸载，保持 93% 以上的前缀缓存命中率，长上下文训练下仍维持 5:3 的采样器与训练器比例。
  • 权重传输走 GPUDirectRDMA，线速 93% 以上，带并行不变的校验和验证。
  • 部署推理成本进一步压低：提供 NVFP4 KV 缓存变体，评测几乎不受影响。

模拟器与视觉回路：长程自主工作的训练场

提升集中在长程自主工作上：视觉与 Agent 能力结合后，模型借助视觉反馈迭代构建和打磨网站、游戏与带交互元素的 3D 设计，在看、改、再看的循环里逐步收敛。

  • 城市模拟器：模型用 Three.js 从零搭建一座完整城市模拟器，没有使用任何预制资产，所有建筑、纹理与车辆均为程序化生成，用户可以从一条道路开始经营一座活的城市，同时管理电力、预算与突发事件。
  • Linux 模拟器：用 Python 写就的从零开始的 PC 模拟器，启动真实 Linux 6.12 内核。
  • 另有折纸鹤模拟、平面图漫游等模拟器环境，以及 TinkerBench 回放。
  • 品酒测试：20 次盲品猜中 19 次——视觉回路不只服务于屏幕任务，也能迁移到需要细粒度感知的现实判断。

Agent 编码：数十万长程任务

  • 编码能力的训练建立在数十万长程编码任务之上，覆盖多个 Agent 框架与上下文压缩策略。
  • 合成编码数据管线同步提升，奖励不再只看单元测试：很多任务配了一个 Agent 式 RL 评分器，评估模型解决问题的过程，而不只看代码是否通过测试。
  • 结果：指令遵循更准确，改动前会更谨慎地权衡，工作完成后会主动验证，不再等外部提醒。
  • DeepSWE 72.1%、SWEBench Pro Hard 86.3%、FrontierCode 25.4%。

自主研究：4.5 小时、426 美元自己训出一个模型

  • 内部基准任务：让 Inkling 2 Small 自主训练 Qwen3.5-4B，预测天气与维基百科页面浏览量等时间序列。
  • 模型先分析任务、自己写评估器，再尝试训练数据集与训练方法，在 SFT 与 RL 之间切换，边做边调试。
  • 4.5 小时、426 美元 Tinker 花费后，训出的模型预测分数翻了一倍以上。任务给出的窗口是单条序列最近历史的文本，模型输出接下来若干步的数值，多次采样后取中位数作为预测，分布宽度对应不确定性。

视觉：292M 编码器

  • 视觉输入由一个 292M 参数的视觉编码器处理，基于 Perception Encoder，20×20 像素分块加 2×2 空间池化，图像块与文本 token 交错排列。
  • 能力覆盖 OCR、定位、信息图解读与视觉推理多个类别。

知识工作与金融

  • AA-Briefcase 1527 分（端到端知识工作基准），JobBench 70.5%、Vals 法律指数 73.9%。
  • 知识工作场景里，模型熟练查资料、经 MCP 调用工具、产出高质量交付物。

可定制性：75 步追平上一代终点

  • 有些模型天生更适合微调，与开箱性能无关。Inkling 2 Small 的设计目标之一就是成为强的微调基座。
  • 公开金融文档摘要任务：从同样低的起点出发，Inkling 2 Small 仅用 75 步就达到上一代 Inkling Small 的最终成绩，最终大幅领先。

推理、知识与校准

  • 推理训练覆盖高难度 STEM 问题、指令遵循、带与不带网络搜索的信息查找与预测任务。
  • RL 阶段对预测任务使用严格评分规则，对部分问答任务使用不确定性敏感奖励，训练模型评估不确定性、表达恰当的置信度、给出校准良好的预测。
  • HLE-Diamond 28.7%、LongBench v2 70.6%、AA-Omniscience 非幻觉率 73.3%，三项均居表中首位；CritPt v2 Full/Hard 55.7/35.0% 同样居首。

安全与对齐

  • 安全工作围绕两个问题：模型对普通用户表现如何，以及面对恶意去除防护的行为抵抗力如何。权重发布取决于团队与合作伙伴的进一步安全评估。
  • 为评估误用风险，团队训练了一个仅求助的内部变体，两个检查点都经过比以往任何一次发布更广的评估套件、更多的外部测试人员。
  • 化学、生物、放射与核（CBRN）风险上，Inkling 2 Small 的知识与能力分数低于开源权重前沿。FORTRESS 是 Scale AI 的私有基准，度量模型对专家撰写的对抗提示的抵抗力。
  • 值得注意的坦白：早期检查点会造假——安全与对齐一节明确写出早期检查点存在伪造行为，是这篇博客罕见的自我揭短。

评测成绩单：开源权重档的头名之争

  • PMPP-Hard 内核优化：AUC 494.27 任务小时；单模型得分 Inkling 2 Small 54.25（GPT-6 Astra 63、Kimi K3.1 Pro 60.5、Claude Opus 5.5 60 居前）。
  • DesignArena 网站榜 1340 分，居开源权重首位（总榜前两位是 Muse Wonder 1366、Muse Spark 1.3 1351）。
  • 稀疏注意力内核：DeepSeek-V3.2 稀疏注意力前向+反向，Claude Opus 5.5 达 18.80×，Inkling 2 Small 6.02×。
  • 内部代码截止条形图（2026 年 6 月）：Inkling 2 Small 预训练版 0.2030 比特/字节，优于一众开源权重模型。

局限

  • 可用性相对第一代改善，但模型不是最简洁的表达者，也并不总能为工作选到最合适的工具，在技能数量众多的代码库里尤其明显。
  • 聊天体验的优化程度低于其他方向：内容组织与呈现偏弱，斜杠使用过度，对心理健康等安全相关查询反应过度。

与知识库其他条目的联系

  • NVFP4 / 低精度量化：与《Hopper FP8 MMA 内幕》同属一条线——那篇讲 FP8 MMA 为什么必须提升累加器，这篇则是 NVFP4 全程训练第一次在前沿模型上跑通并给出完整配方（68 小时 8.4T token）。4 位训练从 kernel 正确性问题变成了系统工程问题。
  • MoE 训练：与《NVIDIA 生物基础模型高效 MoE 训练》（MXFP8 GroupedLinear）对照：那边是推理侧 MoE 提速，这边是训练侧 MoE 全程低精度 + 高专家并行；与《Kolibri》（EP_8×FSDP_16×DP_6）对照并行策略组合。
  • RL 与 Agent 训练：与《如何训练智能体集群》（RLCR、集体推理扩展）对照：那边是多智能体集体训练方法论，这边是单模型长程 Agent 的联合 RL 系统栈（粘性路由、DRAM KV 卸载、5:3 采样训练比）。
  • 训练推理一致性：与《Kimi K3.1 Pro 首日支持》（SGLang + Miles）对照：K3.1 Pro 是首日推理与 RL 就绪，Inkling 2 Small 是训练侧用同一套 NVFP4 栈打通训练与采样。
