一句话要点

LeapQuant 是免训练方法，把线性注意力的递推状态量化到 8bit，模型质量近无损：精度与 FP32 基线相当，状态显存流量降 3.4 倍，端到端显存占用最多降 56%；kernel 层平均提速 2.05~3.70 倍，vLLM 端到端平均快 1.57 倍。

为什么递推状态成了瓶颈

  • Qwen、Kimi、GLM 家族的新模型把许多标准注意力层换成线性注意力（GDN、KDA），上下文压进定长递推状态，长上下文处理更便宜。
  • 但状态本身仍占大量显存带宽与容量：每个生成 token，线性注意力层都要从 HBM 读状态、做一次轻量更新、再写回去，解码卡在显存带宽上；开启前缀缓存时，每个缓存前缀各留一份状态，状态占 GPU 内存的大头。

量化为什么难：两处误差源

  • 误差累积：状态每步解码都递推更新，一次量化引入的舍入误差带进之后全部状态，在长上下文上不断累积。
  • 离群行列：状态里的离群行与离群列拉大量化范围，逼小值落到粗糙的量化级上，每次量化的误差进一步放大。
  • 准确的低 bit 量化要同时做到两件事：少引入误差，每次引入的误差也要小。LeapQuant 的三招各管一端。

三招

窗口量化：隔一个窗口再量化一次

  • 窗口开头把递推状态存成低精度；窗口内固定这个状态，缓存高精度的 token 更新，用固定状态加缓存更新算每个输出；只有窗口结束时才重建完整更新状态并量化，供下一个窗口用。
  • 量化误差引入的次数因此大减：逐 token 量化下误差从 0.5% 累到 10%，逐窗口量化只到 1%。

补偿 token：离群值用高精度外积接住

  • 把状态里最大的离群值用高精度存成少数几个补偿 token：每个补偿 token 是两个向量的高精度外积，同时抓住行与列两个方向的大量级模式，剩下的残差更好量化。
  • 秩一项目与真实 token 更新形式相同，直接放进窗口的更新路径，只多用少数几个向量，不用单独的状态更新。

残差平滑：把行量级拉平再量化

  • 去掉补偿 token 后，残差在各 key 通道上量级仍不均匀，少数大通道会主导量化尺度。量化前平滑残差、平衡各行量级；平滑尺度在窗口内固定，每个窗口边界重新算。
  • 在 Qwen3.5-9B 的一个 head 里，补偿 token 加平滑把离群值从中位量级的 176 倍降到 5.3 倍。

精度：8bit 与 6bit 持平，4bit 只低 3.4 分

  • 下游精度（%，三个 seed 平均），任务 AIME 2026、BeyondAIME、GPQA-Diamond、LiveCodeBench v6，三模型 Qwen3.5-9B、GLM-5.3-Flash、Qwen3.8-Flash-Next。
  • LeapQuant 8bit 平均 84.4 分，与 FP32 的 84.0 相当；6bit 同样 84.4 分；4bit 平均 80.6 分，只低 3.4 分。
  • 对照组崩得厉害：朴素 FP8 在 Qwen3.5-9B 上 AIME 0.0、Beyond 0.1，平均 45.1；INT8 平均 47.7；连 BF16 平均都掉 11.5 分（72.5）。KVQuant、QuaRot、TurboQuant 在 8bit 下平均 61.3~75.2 分。

速度：kernel 2.05~3.70 倍，端到端 1.57 倍

  • 单个线性注意力层：相对 FP32 状态，在 B200、RTX PRO 6000 与 RTX 5090 的 GDN 与 KDA 层上平均提速 2.05~3.70 倍。
  • vLLM 里 4K 上下文纯解码步：最大 batch 下 B200 提速 1.22~1.29 倍，RTX PRO 6000 提速 1.22~1.57 倍；增益随 batch 变大而增长。
  • 接进 vLLM 后端到端平均提速 1.57 倍。

对推理优化的含义

  • 线性注意力把 KV 的显存墙换成了递推状态的显存墙：状态每 token 读改写回，前缀缓存下每份缓存前缀各留一份。量化状态是不动权重、不训参数的解法，收益直接落在解码与端到端吞吐上。
  • 误差要分两处治：窗口量化管引入次数，补偿 token 与残差平滑管每次误差的大小。只做一处不够——逐 token 量化再准也架不住累积，离群值不处理再少量化也没用。
  • 8bit 是甜点：精度与 FP32 持平；6bit 还能持平；4bit 开始掉 3.4 分。选位宽时先看离群结构，不是先看标称精度。
