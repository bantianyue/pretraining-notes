GPU 通信（一）精读：从 IPC 句柄到 NVSwitch 的跨进程共享全链路

  • 原文：GPU Communications - I（个人技术博客，2026-10-22）
  • 评级：⭐⭐⭐⭐（主题 GPU 通信 / 多卡互连 / 推理框架；从页表到 NVSwitch 的全栈梳理，SGLang 落点明确）

一句话要点

GPU 间共享内存不是一个机制，而是四层接力：页表与 pinned 内存决定数据能不能被别的设备访问，/dev/shm 与 IPC 句柄解决跨进程传递，PCIe/NVLink/NVSwitch 决定跨设备带宽与拓扑，SGLang 在此之上做跨进程共享。

机制主线

  1. 基础：页表与 pinned（页锁定）内存是跨设备访问的前提；NUMA 位置决定本地与远端访问的延迟差。
  2. 跨进程：/dev/shm 做共享内存载体，CUDA IPC 句柄把设备内存导出给另一进程；文中含 CPU /dev/shm 演示、CUDA IPC ctypes 演示两段核心代码。
  3. 互连代际：PCIe、NVLink、NVSwitch 三代互连的带宽与拓扑差异是全文唯一真表格承载的对比；NVLink peer kernel 演示点对点访问。
  4. 框架落点：SGLang 的跨进程共享用法建立在上述机制之上；cudaMallocAsync 在特定条件下会拒绝分配，文中以演示代码说明边界。
  5. 两个未带入的点：源站有两段视频动画（一跳 All-reduce、SHARP 组播），微信草稿无法承载视频，已在正文中改文字描述机制。

与已有收藏的关系

  • 与 Blackwell NUMA 精读直接呼应：那篇是单卡内双 Die 的局部性，这篇是多卡与多进程间的共享与互连，两篇合起来是从 Die 内到机群的局部性全景。
  • 与 OCP 协同设计精读互补：那篇讲机群供电/液冷/网络的系统权衡，这篇讲 GPU 通信的机制层实现。
