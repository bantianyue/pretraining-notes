GB200 NVL72 与 Dynamo 如何提升 MoE 推理性能 — 中文精读

原文：NVIDIA GB200 NVL72 和 NVIDIA Dynamo 如何提升 MoE 模型的推理性能（NVIDIA 技术博客，中文站，2025-06） 收藏：2026-11-06，星级 4⭐（重点阅读：推理优化 / MoE 推理架构） 主题：并行策略（推理）/ 推理优化 / MoE 架构 方法：高保真数据中心级 GPU 性能模拟器，数十万个设计点（模拟结果，非实测）

一句话要点

Dynamo 的分解服务（预填充与解码分离、速率匹配、Planner 自动扩缩）加 GB200 NVL72 的 72 卡 NVLink 大域（130 TBps All-to-All），让 DeepSeek R1 在中等延迟下吞吐提升 6 倍，Llama 70B 在同样中延迟下提升最高 3 倍；关键是解码用宽专家并行（每 GPU 约 4 位专家、64 卡容纳全部 256 位路由专家），而宽 EP 只有在大 NVLink 域里才跑得动。

MoE 推理为什么需要新架构

最新一批开源大语言模型采用 MoE 架构（DeepSeek R1、Llama 4、Qwen3）：推理期间只激活专家参数的子集，选择性激活减少计算开销、缩短推理时间、降低部署成本。

但 MoE 的专家路由是多对多通信：DeepSeek R1 每个 token 发给 256 位专家里的 8 位，选定的专家各自算完再经 all-to-all 交换输出。解码阶段在宽 EP 下表现最佳（每 GPU 只托管少量专家，计算分配更均匀、延迟更低，同时 KV 缓存空间更大、每批请求更多），而宽 EP 要求所有专家在同一低延迟、高带宽域里——这正是 GB200 NVL72 的用武之地。

分解服务：预填充与解码分开优化

自 BERT（2018）以来模型权重增长 1000 多倍，生成式推理的吞吐量与交互预期只增不减，常见做法是用 TP、PP、DP 跨多卡分片模型。

传统部署把预填充与解码托管在同一 GPU 或节点上，但两者资源需求不同：令牌并行的预填充与自回归解码的 SLA 各不相同（TTFT 对预填充、ITL 对解码），每个阶段受益于不同的模型并行选择；共置导致资源利用效率低下，尤其对长输入序列。

分解服务把两个阶段分到不同 GPU 或节点，独立优化：应用不同的模型并行策略、分配不同数量的 GPU 满足各阶段需求。MoE 引入新维度 EP（专家并行）：专家分布在各 GPU 间，与 TP、PP、DP 组合，显著扩展模型并行搜索空间。

模拟结果（DeepSeek R1，数十万个并行配置）：中等延迟下，分解服务比共置实现 6 倍吞吐量提升。

Dynamo：解耦服务的自动化

NVIDIA Dynamo 是分布式推理服务框架，专为数据中心规模部署设计，简化并自动化分散式服务架构的复杂性：管理预填充与解码 GPU 之间 KV 缓存的快速传输、把请求智能路由到保存相关 KV 缓存的解码 GPU；需求超过分配容量时，用 Planner 与 Kubernetes 把整个分解设置扩展到数万个 GPU。

速率匹配是关键挑战：预填充与解码 GPU 之间要匹配请求速率，防止解码 GPU 等 KV 缓存时空闲、或预填充在解码主导设置中卡队列。正确的速率平衡要考虑预填充队列中的请求数、解码 GPU 中 KV 缓存内存块利用率、SLA（TTFT、ITL）。速率匹配的最优比例随目标延迟变化（模拟的延迟 SLA 曲线），ISL/OSL 因请求而异又让一致性速率匹配更复杂。

Planner 专用引擎自动化这个过程：评估预填充队列时间、解码 KV 缓存 GPU 显存利用率、应用 SLA，确定 GPU 资源的最佳配置；根据输入输出序列请求不断变化的模式，智能决定扩展的 GPU 类型、方向与比例。Planner 能检测工作负载在长/短 ISL 与 OSL 间的差异，决定用解码 GPU 上的传统聚合部署还是跨预填充/解码 GPU 的解服务。

流量模式：分解服务有利于各种 ISL/OSL 流量模式，尤其长 ISL；四种流量模式的模拟显示，disaggregation 对 prefill-heavy 流量帮助最大。

GB200 NVL72：宽 EP 的硬件底座

DeepSeek R1：每 token 发给 256 位专家里的 8 位；宽 EP 下每 GPU 约 4 位专家，需要 64 个 GPU才能在解码期间容纳全部 256 位路由专家。

多对多通信的网络挑战：参与解码的每位专家必须与为同一 token 选择的其他七位专家交换数据，全部 256 位专家（以及托管它们的 64 个 GPU）必须在同一低延迟、高带宽域中运行；选定专家若在不同节点的 GPU 上，多对多通信会因 InfiniBand 等较慢的节点间协议成为瓶颈。

GB200 NVL72 机架：四个 NVLink 卡式（刺），5000 多根节能同轴铜缆，每个 GPU 与其他 GPU 的通信速度比先进的 Ethernet 标准快 36 倍。

NVLink 域：GB200 NVL72 提供 130 TBps 的 All-to-All 总带宽。对比 HGX H200 基板：单个 NVLink 域最多 8 个 GPU，每 GPU 900 GB/s；GB200 NVL72：NVLink 域支持多达 72 个 NVIDIA Blackwell GPU，每 GPU 1.8 TB/s，比 400 Gbps Ethernet 标准快 36 倍。

模拟结果：更大的 NVLink 域有助于分解服务性能，DeepSeek-R1 受益于更高的 EP 和中延迟批处理。

密集模型同样受益：Llama 70B

GB200 NVL72 与 Dynamo 在 Llama 70B 等传统密集模型上协同工作，同样实现巨大性能提升。

模拟（数百个模型并行配置）：随着 TTFT 约束收紧，tensor parallelism 必须从 2 个 GPU 扩展到 64 个 GPU；严格 TTFT SLA 下，共置与分解服务都有利于高 TP，但分解解码能更积极地实现这一策略。Dynamo 分解解码无需在计算密集的预填充性能与解码速度之间平衡，更好适应日益严格的延迟需求。GB200 NVL72 的纵向扩展架构让 TP 解码部署中的所有 GPU 以高达 260 TBps 的速度用 all-reduce 通信，在高达 3 倍的相同中延迟机制下提高吞吐量。

总结

Dynamo 与 GB200 NVL72 的组合产生强大的复合效果：Dynamo 处理预填充和解码自动缩放、速率匹配，简化并自动化 MoE 模型的解服务复杂挑战；GB200 NVL72 提供独特的纵向扩展架构，加速宽 EP 解码的多对多通信。两者共同助力 AI 工厂更大限度地提高 GPU 利用率，满足更多的每笔投资请求，推动利润持续增长。
