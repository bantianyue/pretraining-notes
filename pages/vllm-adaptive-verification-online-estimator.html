vLLM 自适应验证：无置信度头时的在线接受率估计器 —— 中文精读

原文：Adaptive Verification Without a Confidence Head（vLLM 博客，2026-10-14） 星级：⭐⭐⭐⭐ 重点阅读｜主题：推理优化、推测解码（speculative decoding） 收藏日期：2026-10-15｜一句话：vLLM 给无置信度头的草稿模型补上自适应验证——逻辑回归从草稿 logits 提单个标量在线预测接受概率，K+1 个参数，AUC 0.83 追平训练好的置信度头。

1. 背景：自适应验证（AV）

推测解码中，AV 只验证草稿 token 的一个子集：接受概率低的在目标模型前向之前先从 batch 里剪掉，省算力。大 batch 下 GPU 计算受限时最划算。

AV 需要逐 token 的接受概率估计，此前只有带置信度头的 DSpark 草稿模型能用。置信度头是草稿隐状态上每个位置的小线性层，训成"目标会不会接受这个 token"的二分类器。

2. 问题：EAGLE/MTP/DFlash 被排除在外

没有置信度头的草稿模型（EAGLE、MTP、DFlash、部分 DSpark checkpoint）完全用不上 AV。加头意味着重训，对存量 checkpoint 不是选项。

3. 方案：logit(qmax) 特征 + 在线逻辑回归

从草稿分布提单个标量——草稿最可能 token 的 log-odds，即 logit(qmax)，直觉上是草稿对自己预测的确信度。逐位置逻辑回归：共享斜率 ω + 逐位置截距 βi，K token 草稿模型共 K+1 个参数。sigmoid 输出即估计接受率，直接用作 AV 置信度分数。

参数在线拟合：用目标模型正常验证本来就要产生的接受/拒绝判定做标签（只取到第一次拒绝为止的 token），IRLS 最小化对数似然损失。每 N 个 decode 步重拟合一次，区间内累积 Hessian/梯度，内存上界 O(K²)（而非收原始标签的 O(N×B×K)）。

两个工程细节： - 共享斜率：深层位置标签稀疏，共享防止 noisy 更新；实测只差 0.0002 AUC / 0.0003 log-loss。 - 步长阻尼：更新按 n/(n+常数) 缩放，标签少的深层走得保守。

4. 为什么是 logit(qmax)：四个维度的取舍

评估轴：无损性（硬门槛，不能打破推测解码输出目标精确分布的保证）、AUC（区分度）、log-loss（罚自信的错）、ECE（校准）。

  • logit(qsampled) / -log(-log(qsampled))：AUC 更高（0.855），但有损——按 qsampled 剪枝让"验不验"依赖于 xi 本身，活下来的草稿不再服从 q 分布，拒绝采样的 min(1,p/q) 前提被破坏。
  • qmax 直接当概率（EAGLE-2 做法）：AUC 0.8259 甚至超过置信度头（0.8191），但校准极差（平均预测 0.784 vs 实际 0.723，ECE 差 7 倍）。草稿的确信 ≠ 目标认不认，还受采样配置和负载影响。
  • logit(qmax)：AUC 0.8336 / ECE 0.0100，平衡最好，且与被估计量同处 log-odds 尺度。

AV 要的不只是排序：预算决策把预测接受概率加总再除以实测成本，依赖的是校准——这是在线拟合相对离线映射的核心优势。

5. 对阵置信度头：赢在修剪发生的位置

AUC log-loss ECE
估计器 0.8336 0.4284 0.0100
置信度头 0.8191 0.4449 0.0052

去掉第 0 个草稿位置后：估计器 AUC 0.8352 vs 头 0.8075，ECE 基本打平（0.0103 vs 0.0090）。逐位置分解：头只在第 0 位领先，估计器从第 1 位起反超，到最后一位领先 0.08 AUC；两者都在第 5 位后下滑（DSpark block size=5，没训过更深）。

关键洞察：survival 是连乘，第 0 位永远是单请求最高分、最不容易被预算裁掉——估计器的优势正好长在修剪发生的位置，所以端到端能追平置信度头。

6. 斜率与截距的分工

固定模型对换负载：斜率几乎不动（0.51–0.55，与草稿熵 r=-0.08）；截距随负载动（第 0 位截距与草稿熵 r=-0.89）。换模型对：斜率 0.45–0.59，每对内部稳定。

分工：斜率衡量草稿模型"知不知道自己对了"（模型对+采样方式的属性）；截距吸收基础接受率（随深度下降、难内容更低，同时依赖模型对和负载）。

7. 实测与局限

三个此前用不上 AV 的 checkpoint（MiMo-V2.5-Pro-FP4+DFlash、Inkling-NVFP4+MTP、Muse-Glimmer-30B+DFlash2）：7 个并发中有 5 个，AV 落在吞吐-交互性前沿上。

局限：目标注意力后端须支持变长验证；MTP/EAGLE 收益小于 DFlash/DSpark（自回归推测器为可能被剪的 token 付的起草成本占比更大）。

使用：--speculative-config 加 "enable_adaptive_verification": true，满足"无置信度头+变长注意力"时自动选用在线估计器。
