HyScale：FlashTopK 免分数表选 top-k，GLM-5.1 百万 token 训练快 2.07 倍（中文精读）

  • 原文链接：https://arxiv.org/abs/2610.32057
  • 收藏日期：2026-11-14

  • 主题：长上下文训练 / 稀疏注意力 / Kernel 优化

一句话要点

选分的输出不是连续激活，而是一组离散下标：FlashTopK 边打分边选 top-k，分数表永不落盘；选择重放让重算只重打 k 个分。512 张 H20 上，GLM-5.1 百万 token 训练快 2.07 倍。

瓶颈在哪

  • 学习型稀疏注意力每 query 只读 k 个 token，但选分要给每个 query 的全部历史 token 打分：Megatron-LM 训 GLM-5.1 时，1M 上下文下选分独占单步的 47%，是稀疏注意力本身的 6.6 倍。
  • 选分慢的根子在分数表：给 L 个 token 打分要写一张 L 大小的分数表，再读回来选 top-k；表越大，访存越贵。
  • 更深的问题在重算：反向重算前向时，选分也要重打一遍，O(L) 的选分在重算里又付一次。

FlashTopK：边打分边选

  • 洞察是选分输出只是下标：top-k 的结果是一组 token 下标，不需要把整张分数表写下来。
  • FlashTopK 用乐观阈值边打分边选：先给阈值定一个乐观估计，打分过程中动态收紧，只保留高于阈值的候选；分数表永不落盘。
  • 效果：FlashTopK 比 cuDNN 快 1.84–2.80 倍；分数表 32 GiB 变成下标索引 64 MiB；前向选分 35.9 秒 → 20.8 秒。
  • 失败率极低：随机权重下 82% 的选分会失败（阈值估计失效），FlashTopK 的失败只有 5 / 81.8M，少 15,000 倍；训练早期的数值爆炸（17 倍 / 13 倍）也被压住。

选择重放：重算只重打 k 个分

  • 前向把选出的下标留下来；反向重算时，只对这 k 个 token 重新打分，不用重扫全部 L 个历史 token。
  • 选分重算从 O(L) 降到 O(k)：重算选分 37.0 秒 → 1.0 秒；流水线等待 106.6 秒 → 51.7 秒。
  • 两个 top-k 集合高度重合：共享 top-2048 占 71%，并集只有 1.29 倍；重放的下标与重算的下标基本一致，精度不受损。

端到端效果

  • GLM-5.1 百万 token 训练：512 张 H20 上快 2.07 倍；256K 上下文 1.23 倍，512K 上下文 1.44 倍。
  • 块级 CSA 与 QSA 层：1M 上下文、32 张 H800 上分别快 2.01 倍与 1.57 倍。
  • 步时间：HyScale 步时间只涨 1.27 倍（上下文 128K → 8M），基线涨 2.13 倍；MFU 从 20.9% 升到 27.8%，基线从 17.1% 跌到 13.5%。
  • 强扩展：到 256 卡，每翻倍快 1.65–1.96 倍；弱扩展：128K → 8M 上下文，HyScale 总耗时只涨 11 倍，基线涨 190 倍，加速比从 1.24 倍拉到 22.3 倍。
  • 消融：三项改进共省 66% 步时间——FlashTopK 37%、选择重放 18%、系统优化 11%。

硬件层面的观察

  • 选分是访存 bound：L2 缺失率 53–65%，warp 停顿 40–44%，Tensor Core 利用率只有 21–32%；FlashTopK 把分数表从 HBM 里拿掉，直接对症。
  • 显存占用：FlashTopK 选分只用 1.3–1.4 GiB，对照组 3.1 GiB 与 12–48 GiB；百万 token 训练不再被分数表卡显存。

结语

  • 稀疏注意力的瓶颈不在注意力本身，在选分；选分输出是下标这个性质，让分数表可以根本不写、重算可以只重打 k 个。
  • 这套打法不依赖特定稀疏模式：任何"选分输出是下标"的学习型稀疏注意力都能用；下一步是把同样的思路推到推理侧的选分与 KV 选择上。
