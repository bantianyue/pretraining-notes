vLLM 生产环境监控指标（Production Metrics）· 中文精读

原文：https://docs.vllm.ai/en/latest/usage/metrics/（vLLM 官方文档） 精读日期：2026-09-30 ｜ 主题：推理可观测

0. 怎么用

指标通过 OpenAI 兼容 API server 的 /metrics 端点暴露（Prometheus 格式）：

vllm serve unsloth/Llama-3.2-1B-Instruct
curl http://0.0.0.0:8000/metrics

1. 通用指标（General Metrics）

请求与 token（Counter）

指标 含义
vllm:request_success 成功处理的请求数
vllm:prompt_tokens 处理的 prefill token 数
vllm:generation_tokens 处理的生成 token 数
vllm:prompt_tokens_cached 命中的缓存 prompt token 数（本地+外部）
vllm:prefix_cache_hits / _queries 前缀缓存命中 / 查询（token 数）→ 算命中率
vllm:external_prefix_cache_hits / _queries 跨实例 KV 共享的外部前缀缓存
vllm:num_preemptions 累计被抢占次数（KV cache 不够时请求被换出）
vllm:corrupted_requests logits 出现 NaN 的坏请求数

实时状态（Gauge）

指标 含义
vllm:kv_cache_usage_perc KV cache 使用率（1 = 100%）——容量规划的核心指标
vllm:num_requests_running 正在执行 batch 中的请求数
vllm:num_requests_waiting 等待调度的请求数
vllm:num_requests_waiting_by_reason 按原因细分的等待数：capacity（等调度容量）/deferred（LoRA 预算、KV 传输等临时约束）
vllm:lora_requests_info LoRA 请求运行统计
vllm:engine_sleep_state 引擎休眠状态

延迟（Histogram）——定位瓶颈用

指标 含义 对应优化方向
vllm:time_to_first_token_seconds TTFT prefill 慢？看 prefill CP、chunked prefill
vllm:request_prefill_time_seconds 请求在 PREFILL 阶段耗时 同上
vllm:request_decode_time_seconds 请求在 DECODE 阶段耗时 decode 慢？看 KV cache、DCP、MTP
vllm:request_queue_time_seconds 请求在 WAITING 阶段耗时（排队） 排队久？KV cache 不够或 batch 太小
vllm:inter_token_latency_seconds token 间延迟 流式体验
vllm:time_per_output_token_seconds 每个输出 token 耗时 decode 吞吐
vllm:e2e_request_latency_seconds 端到端延迟 总账
vllm:iteration_tokens_total 每个 engine step 的 token 数 batch 饱和度
vllm:request_num_preemptions 单个请求被抢占次数分布 抢占频繁 → KV 压力大

KV cache 块生命周期（采样指标，--kv-cache-metrics-sample 控制）

  • vllm:kv_block_idle_before_evict_seconds：块被驱逐前的空闲时长
  • vllm:kv_block_lifetime_seconds：块从分配到驱逐的存活时长
  • vllm:kv_block_reuse_gap_seconds：相邻两次访问的时间间隔（ring buffer，只记最近）

这三个用来分析 KV cache 的复用效率和驱逐策略是否合理。

2. 推测解码指标

  • vllm:spec_decode_num_accepted_tokens_per_pos：每个 draft 位置被接受的 token 数 → 算接受率，调 draft 模型/长度。

3. MFU 性能指标（--enable-mfu-metrics 开启）

  • vllm:estimated_flops_per_gpu_total：每 GPU 估算 FLOPs
  • vllm:estimated_read/write_bytes_per_gpu_total：每 GPU 估算访存字节

用来算 Model FLOPs Utilization，判断是算力 bound 还是访存 bound。

4. KV 相关连接器指标（NIXL / CPU offload）

  • NIXL KV connector：传输失败数、过期请求数、传输字节数/耗时（vllm:nixl_*）——做 PD 分离、KV 跨实例传输时看。
  • SimpleCPUOffloadConnector：offload 池的 load/save 块数、pending 块数（vllm:simple_kv_offload_*）——pending 持续增长说明传输卡住。

5. 废弃策略

X.Y 版本废弃的指标在 X.Y+1 隐藏（可用 --show-hidden-metrics-for-version=X.Y 找回），X.Y+2 删除。做监控看板时注意版本。

6. 排障速查

  • TTFT 高 → 看 request_prefill_time_seconds + kv_cache_usage_perc（cache 满会导致 prefill 排队）
  • decode 慢 → 看 request_decode_time_seconds + time_per_output_token_seconds
  • 请求排队久 → 看 num_requests_waiting_by_reason 区分是容量问题还是 LoRA/KV 约束
  • 吞吐上不去但 GPU 不忙 → 看 iteration_tokens_total（batch 没打满）+ num_preemptions（频繁抢占）
