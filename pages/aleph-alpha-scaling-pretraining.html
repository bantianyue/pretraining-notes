0. 一句话总览

Aleph Alpha 实战复盘：30B-A3B MoE 模型从 16 张扩到 512 张 B200，只在小规模（16 卡）做搜索、用"分层"方法把结论搬到目标规模，最终 35.3% MFU，单卡效率只掉 6%，近似线性扩展。堆栈是自研优化版 torchtitan fork，64 节点 IB 互联、每节点 8×B200（NVLink）。

1. 指标：MFU 是好的，TPS 更好

  • TPS（每卡每秒 token 数）：粗糙但诚实的速度度量，是他们真正优化的目标；
  • MFU：TPS 相对硬件峰值 FLOPS 的效率分数（BF16 峰值为分母），行业通用指标，用于横向对比；
  • mem：PyTorch reserved 内存 / 设备总量（reserved 决定 OOM 硬失败）。
  • 核心工程主题：通信-计算比——目标永远是 compute-bound，让通信 kernel（all_gather/reduce_scatter）被计算 kernel 完全掩盖。

2. 三个自由度

  1. 并行策略（torchtitan 命名）：FSDP（ZeRO-3，权重/梯度/优化器状态分片，all_gather + reduce_scatter）× DP（模型副本数，all_reduce 平均梯度）；
  2. Activation Checkpointing：full-AC（只存每层输入，重算最多）/ selective-AC（只存 attention/linear 等重算贵的算子）/ no-AC（全存）；
  3. Local batch size：每卡每轮同时处理的序列数，直接决定 activation 内存占用。
  4. 约束：ga = gbs / (lbs × n_gpus) 必须为正整数（gradient accumulation 步数），ga=1 时的 all_reduce 只需在最后一次 backward 做（其余步可省掉 DP 通信）。
  5. 三个旋钮互相牵制：AC 策略决定内存→决定能放多大 lbs；FSDP 组越大权重分片越细→能放大 lbs→但通信组变大。

3. 分层方法：16 卡先把搜索空间打穿

基本单元 = 一个节点（8×B200）。在 8–16 卡做最大规模 sweep：FSDP∈{8,16} × DP∈{1,2} × AC∈{no/selective/full} × lbs 逐级扫到 OOM（seq_len 固定 4096）。 - 16 卡峰值：28.4k TPS / 37.5% MFU；selective-AC 在 lbs≈18 达到峰值（92% 显存），full-AC 在 lbs≈38 达到峰值； - no-AC 小 batch 最快但 OOM 太早，退出竞争； - 8→16 卡跨节点（IB）TPS 无明显下降 → 通信介质够快，保持 compute-bound。 - 结论：把 1/32 规模的结论（峰值 lbs 区间、最优 AC、FSDP 上限）直接带到大规摸，只在峰值附近微调，不再全空间重扫。

4. Profile 驱动：PyTorch trace 看通信掩盖

用 Perfetto 分析 trace，按 kernel 类型分组（all_gather / GEMM / Attention / Norm）： - 前向：下一层的 all_gather 预取与当前层计算完全重叠，compute stream 背靠背 → compute-bound； - 反向：reduce_scatter 同样被计算掩盖；引入 DP 后多出 all_reduce（只在最后一步做），形成 DP vs FSDP 的 push-pull：DP 度数越大 FSDP 组越小、通信越轻，反之亦然； - 小但实在的优化：backward 到下一次 forward 之间让权重常驻显存不重新分片/聚拢，目标规模约 +2~3% 吞吐。

5. 放大到 512 卡：FSDP 到头了，剩下的交给 DP

  • 128 卡（FSDP=128）：selective-AC 28.0k TPS / 37.0% MFU（只掉 1.4%），full-AC 26.3k / 34.7%；
  • 前向通信已到"通信-bound"边界、反向仍明显 compute-bound → 128 是 FSDP 度数的上限；
  • 512 卡最终配置：selective-AC, lbs=22, FSDP=128, DP=4 → 26.7k TPS / 35.3% MFU / 94% 显存；
  • 16→512 卡单卡效率只掉 6%。按此效率，20T token 在 512 卡上约 17 天；再加 DP 副本可压到 11 天。

6. 与知识库其他内容的关系

  • 这是"并行策略如何组合"的完整实战：FSDP×DP 的度数分配、AC 与 lbs 的联动、profile 验证通信掩盖——正好是学习目标达标标准里的核心项；
  • 与 MLSysBook 分布式训练章互补：那边讲 fleet law 和并行原语，这边讲"16 卡小规模搜索 → 512 卡放大"的工程方法论；
  • EP（专家并行）被明确排除在外——30B-A3B 这个规模/稀疏度下通信计算比已经能靠 FSDP+DP 摆平，模型更大更稀疏才需要 EP（呼应 abcdabcd987（二）极简并行方案中 EP 的角色）；
  • 局限：只验证了单一架构 + 4096 序列长度 + FSDP/DP；系统级和 kernel 级优化（35.3% MFU 的地基）不在本文范围内。
