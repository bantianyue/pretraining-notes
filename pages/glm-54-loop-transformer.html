GLM-5.4：28层循环跑两遍，750B模型追平2T-3T参数模型（中文精读）

  • 原文：Toward Generalized Coding with Our First Loop Transformer（z.ai，2026-11-23）
  • 收藏：2026-11-24，4⭐
  • 主题：循环架构、训练核心流程、KV 缓存、推理优化、通用编码
  • 一句话要点：GLM-5.4 把 750B 基座的 28 层循环跑两遍，不增加参数，智能水平达到与 2T-3T 参数模型相当；门控渐进更新、混合 KV 缓存、稀疏注意力索引复用三处改动控制了多一轮循环的代价。

为什么值得读

这篇是循环 Transformer（Loop Transformer）第一次上旗舰模型规模的实证：不是小模型玩具，而是 750B 基座、28 层跑两遍，智能水平追上 2T-3T 参数模型。文章的价值不在发布本身，而在它把"深度"从"规模"里拆了出来——参数不增加，靠权重共享层多跑一遍换来更深网络，并给出了等参数对照的硬数字：30B 模型、相同参数、多约 10% 训练算力，AIME25 从 19.17 升到 30.42，GPQA-Diamond 从 47.58 升到 56.26，思考 token 反而少了 10%–14%。三处架构改动的写法也很实在：门控怎么写、KV 怎么省、索引怎么复用，都有具体机制，没有一句空话。

核心结论

  • 循环换深度，不换参数。标准 Transformer 每层每次前向只跑一遍；循环 Transformer 里一组权重共享层跑多遍，每遍精炼上一遍的隐状态。网络更深了，参数没有增加。GLM-5.4 循环的是 GLM-5 基座的 28 层（L27–54），跑两遍。
  • 750B 规模上智能水平达到与 2T-3T 参数模型相当。过去三个月团队并行扩展了循环深度与模型规模，第一份惊喜来自循环架构本身：共享权重块多跑几遍，模型推理更深，效果追上大得多的模型。
  • 等参数对照的收益是实测的。30B 模型、与 750B 基座完全相同的架构、参数量相同、总训练算力只多约 10%，循环版明显占优；多数基准的平均输出长度下降 10%–14%，主要来自更短的思维链。
  • 推理峰值 70–80 token/秒，闲时 200 token/秒。多遍循环架构跑出这个吞吐，需要模型与推理基础设施的紧密协同设计：KV 缓存与稀疏索引省显存、省检索，系统层面融合核心算子，减少中间显存读写，消除循环放大的碎片化开销。

循环架构：三段式

  • 前奏 26 层（L1–26），循环段 28 层（L27–54，权重共享，跑两遍），尾段 24 层（L55–78），最后接 LM Head。输入是文本嵌入加投影后的 24 层 ViT 特征。
  • 动机来自任务性质。GLM-5.3 技术博客里提到过：记忆密集型任务受益于更多参数，推理密集型任务受益于更有效的算力。大规模软件工程、网络安全、3D 建模、物理控制都是超长链推理任务：模型必须沿着多步因果链推进，同时保持全局逻辑一致。堆参数、背数据解决不了这个问题。
  • 不是从头训出来的。2018 年的 Universal Transformer 提出了权重共享深度，近年的循环深度与循环语言模型研究也在小规模上见到了收益。但从头训练的循环模型在同样的预训练算力预算下仍落后于非共享模型。智谱没有从头预训练，而是把已有的预训练基座通过继续训练改造成循环 Transformer：用相对较小的算力开销，把智能上限抬高。

三处架构改动

  1. 门控渐进更新。把已有模型的中层改造成多遍循环时，直接覆盖隐状态会让激活范数在迭代间爆炸，下游层收到的表示超出预期的尺度与分布。GLM-5.4 给每次迭代加了独立的逐 token 门，按比例把候选更新写回残差流：第一遍的更新写作 x₁ = x₀ + β₁(h₁ - x₀)，第二遍是 x₂ = x₁ + β₂(h₂ - x₁)。训练后，这些门形成了明确分工：第一遍构建全局上下文，用较小的门值保守写入以保持尺度稳定；第二遍复用这个状态精炼输出，打开门写入完整更新。门还会根据 token 难度动态调整步长：更难的 token，第一遍写得更积极，让复杂预测从迭代精炼中获益更多。
  2. 混合 KV 缓存：全局共享加独立滑窗。朴素做法是给每次循环迭代各留一份完整 KV 缓存，显存用量随循环次数成倍涨。GLM-5.4 在跨循环 KV 共享的基础上，给新一遍补了一个局部滑窗：第二轮复用第一轮选出的稀疏 KV，同时在滑窗内保留自己新生成的 KV。两路 KV 流可以在同一位置重叠，让模型既能注意到第一遍的上下文表示，也能注意到第二遍更新后的局部表示。结果是，多一轮循环只多一个滑窗的 KV 缓存，而不是一整份上下文缓存。架构图里，每层缓存留的是 KV latent 加 top-k（k 取 2048），第二遍的滑窗是 128 个 token。在 1M 上下文长度下，GLM-5.4 相对 GLM-5.3 的部署成本增加控制得很好。
  3. 稀疏注意力索引复用。GLM-5.4 的基座模型用稀疏注意力。第二轮直接复用第一轮索引器生成的注意力索引，零索引开销。实验表明，这与每遍都重新算索引的效果几乎相同。架构图里，每组 DSA Block 只有第一层带索引器，其余层直接复用 top-k 索引；第二遍的注意力是双 bank 稀疏 MLA，稀疏前缀与局部滑窗共用一次 softmax。

缩放正确性与等参数对照

  • 循环是对缩放正确性的一次严格检验：任何架构改动都必须在规模上仍然成立。在把旗舰模型交给循环架构之前，团队在 1B、4B、30B、750B 基座模型上逐步验证了循环架构。
  • 对照结果（30B 模型，200K 长上下文 SFT 后评估，思考模式开启）：
基准 基线 加循环 提升 平均长度变化
AIME25 19.17 30.42 11.3 -635 tokens (-2%)
GPQA-Diamond 47.58 56.26 8.7 -2,473 tokens (-11.7%)
AA-LCR 40.33 47.67 7.3 -539 tokens (-9.7%)
MMLU-Pro 71.65 75.05 3.4 -863 tokens (-14.9%)
IFBench 50.20 53.47 3.3 -763 tokens (-13.0%)
  • 更长的推理链受益更多。提升最大的出现在数学、科学推理与长上下文任务上，而这些正是通用编码的核心。
  • 思考用的 token 更少。多数基准上平均输出长度下降 10%–14%，主要来自更短的思维链。实际上，部分推理从显式输出 token 转移到了循环的隐式深度里。

通用编码：四个演示

  • 视频：GLM-5.4 用代码生成并编辑视频，做出了自述的音乐视频《Hello World》。
  • 工程：FreeCAD 里工程级 CAD 建模，做出六轴机械臂。
  • 游戏：直接做出完整游戏，角色移动、物理、地图、战斗系统与美术资产齐全。
  • 3D：纯数学几何与自定义 GLSL 着色器，从零生成交互式 3D 微距观鸟体验。

局限与下一步

  • 马拉松式思考。模型容易陷入过长的"马拉松式思考"循环，不过这种长时间反思与自我纠正确实把准确率推到了参数规模之上。
  • 开放问题有两个：怎么实现自适应算力，让更难的 token 动态获得更多迭代；随着循环次数与模型规模继续增长，循环的收益如何变化。
  • 两个方向都追。团队不是在扩展深度与扩展模型规模之间二选一，而是两者都追：GLM-5.4 验证了计算深度，下一个大得多的模型会带上这里学到的全部经验，很快就绪。模型权重计划在完成必要的安全加固后负责任地开源。

可复用的点

  • 已训好的基座可以"改造成"新架构，不必从头训。循环 Transformer 从头训练在同等算力预算下落后于非共享模型，但把已有预训练基座通过继续训练改造成循环版，只用相对较小的算力开销就抬高了智能上限。架构创新不一定非要从头预训练。
  • 门控是改造旧模型的关键。直接覆盖隐状态会让激活范数爆炸；逐 token 门按比例写回残差流，第一遍保守建上下文、第二遍放开精炼输出，分工是训练后自己长出来的。
  • KV 成本可以按"增量"算。跨循环共享稀疏 KV、每遍只补一个滑窗，多一轮循环只多一个滑窗的缓存；1M 上下文下部署成本增加可控。循环次数上去之后，KV 预算按滑窗数线性长，而不是按上下文长度乘循环次数。
  • 等参数对照是架构 claim 的试金石。参数量相同、算力只多约 10%，循环版在数学与科学推理上大涨、思考 token 反而更少——这组数字比"追平 2T-3T 参数模型"的 headline 更能说明循环的收益。
