Blackwell NUMA 精读：单颗 GPU 里的两个局部性域

  • 原文：Blackwell Brings NUMA Back, Inside One GPU（Vincent Zhong 个人博客，2026-10-23）
  • 评级：⭐⭐⭐⭐（主题 GPU Kernel 优化 / NUMA / MoE；DeepGEMM MegaMoE 的实测机制，含完整探测与调度代码）

一句话要点

B200/B300 软件上是一块 GPU，物理上是两颗经 NV-HBI 相连的 Die；DeepGEMM 的 MegaMoE 把每颗 Die 当作独立局部性域：先实测 SM 归属，再把权重沿 N 切半分置，最后用亲和调度让 SM 只读本 Die，跨 Die 窃取只在 2 波以上工作时才允许。

机制主线

  1. 问题：CUDA 呈现一个设备、平坦地址空间与统一 L2，但本 Die 的 HBM 明显近于另一颗 Die 的 HBM；MoE 层忽视局部性会把一半权重跨链路拉取。
  2. 定位：CUDA 无接口告知 SM 属于哪颗 Die，DeepGEMM 用指针追逐实测：每 SM 一个 32 线程块占满共享内存、仅 thread 0 追逐，ld.global.cg 绕 L1、事前刷 L2，测 HBM 往返延迟；8 块中位数定归属，远 Die 慢 1.25 倍以上且同 TPC 两 SM 一致才接受，最多重试 5 次否则均分；收割 SM 的不对称靠重分少量 TPC 补齐 50-50。
  3. 切分：权重沿 N 切分，(B, N, K) 变成 (2, B, N/2, K)，第 d 片存入第 d 颗 Die 的 HBM；虚拟地址映射经 cuMemAddressReserve/cuMemMap 实现，CUDA 13.4 前按 Die 分配靠 MLOPart（MPS 模式，每 Die 暴露为独立设备）绕过。
  4. 调度：持久化调度器每 Die 配独立任务计数器，任务映射到本 Die 的半个 N；跨 Die 窃取只在层内工作达到 2 波以上时允许，小层直接跳过；权衡是窃取的延迟与链路占用 vs 本地 Die 空闲。
  5. 寻址：TMA 描述符是 4 维 [K, N/2, die, expert]，CTA 用坐标选半，die 维步长直接跨物理切分；正常时坐标与 SM 所在 Die 一致，内层循环无分支、无地址重算。
  6. 收益：发布说明提到省约 100W 封装功耗，重载下 GPU 时钟高 5-10%。

与已有收藏的关系

  • 与 GPU 通信精读直接呼应：那篇是多卡与多进程间的共享与互连，这篇是单卡内双 Die 的局部性，两篇合起来是从 Die 内到机群的局部性全景。
  • 与 CUDA 启动队列精读同属“实测驱动的性能机制”一类：瓶颈不在算力，而在数据与任务到达计算单元的路径上。
