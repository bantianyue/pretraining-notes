0. 一句话总览

从第一性原理手写 CUDA GEMM：naive → coalesced → shared-memory tiled → 1D/2D register tiled。每一次优化都把瓶颈往计算单元推近一层——GEMM 的方程从没变过，变的是数据的"所有权"和复用层级。

1. 优化阶梯（对应原文 #comparing-the-kernels 对比表）

Kernel 每线程输出数 改了什么 还剩什么代价
Naive row-first 1 直接实现 A 读和 C 写都是跨步访问（stride）
Coalesced direct 1 x 方向线程负责连续列 输入仍为每个输出重复请求
Shared-memory tiled 1 一次全局加载供整个 block 复用 每次乘加仍要 2 次 shared memory 加载
1D register tiled T_M 复用一个 B 值 只在一个方向复用
2D register tiled T_M×T_N 两个输入 fragment 都复用 寄存器压力

三句话版本： - coalescing：让相邻线程请求相邻内存； - shared tiling：让一次全局加载服务多个线程； - register tiling：让一次 shared memory 加载服务一个线程的多个输出。

2. 关键细节

  • Naive kernel 的算术强度：约 0.25 FLOPs/byte，memory bound。更糟的是访存模式：warp 内相邻线程读 A 的值相隔 K 个元素，按 32-byte sector 模型，A 读取效率只有 12.5%（1024 字节传了只用 128）。
  • Coalescing 修复：把 threadIdx.x 映射到输出列，相邻线程读 B 的连续值、写 C 的连续值。单步 dot 的输入流量从 1056 字节降到 160 字节，C 写小 8 倍。但coalescing 只修了"怎么请求"，没修"请求多少次"——A 仍被请求 MNK 次（实际只有 MK 个值）。
  • Shared memory tiling：block 拥有固定的 C 输出 tile，沿 K 维度走，每次加载一对 A/B 输入 tile 进 shared memory，累加 partial 结果。全局加载次数大降。
  • Register tiling：线程拥有 micro-tile（如 8×8），从 shared memory 加载短 fragment，做 outer product，两边 fragment 都被复用多次。16 次 shared 加载产生 64 次乘加（原来只能产生 8 次）。
  • Tile 不是越大越好：shared memory 容量、寄存器压力、occupancy、边缘浪费、矩阵形状都会影响。寄存器不够会 spill 到 local memory，前功尽弃。最终 kernel 取 B_M=B_N=128、B_K=8、T_M=T_N=8（block 256 线程）。

3. Takeaways（原文）

  1. GEMM 的高算术强度只是"机会"，kernel 必须让复用真正发生；
  2. 线程映射在 tiling 之前就重要（threadIdx.x 变化最快 → 映射到列）；
  3. Coalescing 和复用是两回事；
  4. 一个 block 拥有一个固定的输出 tile；
  5. Shared tiling 只是第一级复用；register tiling 让一个线程拥有多个输出；
  6. 大 tile 不自动更好。
