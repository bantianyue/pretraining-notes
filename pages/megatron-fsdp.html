Overview概述

Megatron-FSDP is an NVIDIA-developed distributed parallelism library written in native PyTorch that provides a high-performance implementation of Fully Sharded Data Parallelism (FSDP). It offers seamless cross-compatibility with various deep learning frameworks and parallelism libraries such as Megatron-Core, and is performance-optimized to support training and inference of extremely large PyTorch models at data-center scale on NVIDIA GPUs.

Megatron-FSDP 是 NVIDIA 用原生 PyTorch 编写的分布式并行库，提供全分片数据并行（Fully Sharded Data Parallelism，FSDP）的高性能实现。它能与各类深度学习框架和并行库（如 Megatron-Core）无缝互操作，并针对性能做过专门优化，以支撑在 NVIDIA GPU 上、数据中心规模下对超大 PyTorch 模型做训练与推理。

  2. Advanced Bucketing: dtype-customizable and precision-aware bucketing system to tune the memory overhead, numerical accuracy, and latency of collectives. Avoids redundant COPY operations before and after collectives, while remaining compatible with DTensor features such as Torch Distributed Checkpoint (DCP).高级分桶：可自定义 dtype、能感知精度的分桶系统，用来调节集合通信的显存开销、数值精度与延迟。它避免了集合通信前后的冗余拷贝（COPY）操作，同时仍兼容 DTensor 的特性（如 Torch 分布式检查点 DCP）。
  3. Buffer Management: Efficient use of storage and NCCL User Buffer Registration enable direct communication into NCCL-managed memory, achieving true zero-COPY data movement. Introduced in NCCL v2.27, NCCL Symmetric Memory communications employ symmetric kernels that drastically reduce SM utilization and include networking optimizations such as high-precision (FP32) reduction over-the-wire.缓冲区管理：高效的存储利用加上 NCCL 用户缓冲区注册（User Buffer Registration），让数据可以直接在 NCCL 管理的内存中通信，实现真正的零拷贝数据搬运。NCCL v2.27 引入的 NCCL 对称内存（Symmetric Memory）通信使用对称内核，大幅降低 SM 占用率，并包含高精度（FP32）线上归约等网络层优化。
  4. Optimized Communication & SM Utilization via SHARP: Leverages SHARP (Scalable Hierarchical Aggregation and Reduction Protocol) to offload FSDP collectives to network switches (InfiniBand or NVLink-Switch) and significantly reduce utilization of GPU streaming multi-processors (SM) from 16-32 to 1-6 for Multi-Node NVLink (MNNVL) systems (Grace-Blackwell, Vera-Rubin, etc.), which lowers communication latency in large scaled-out workloads and frees up GPU-hosted processors for overlapped compute (GEMM) kernels. When FSDP sharding domains span both NVLink and InfiniBand, hierarchical SHARP collectives (NVL-SHARP and IB-SHARP) optimize communication paths across the entire system topology.借 SHARP 优化通信与 SM 占用：利用 SHARP（可扩展分层聚合与归约协议，Scalable Hierarchical Aggregation and Reduction Protocol）把 FSDP 的集合通信卸载到网络交换机（InfiniBand 或 NVLink-Switch）上。在多节点 NVLink（Multi-Node NVLink，MNNVL）系统（Grace-Blackwell、Vera-Rubin 等）中，这能把 GPU 流式多处理器（SM）的占用从 16–32 降到 1–6，从而降低大规模横向扩展负载下的通信延迟，并腾出 GPU 上的处理器资源跑可重叠的计算（GEMM）内核。当 FSDP 的分片域同时跨 NVLink 和 InfiniBand 时，分层 SHARP 集合通信（NVL-SHARP 与 IB-SHARP）会沿整个系统拓扑优化通信路径。
  5. Hybrid-FSDP (HFSDP), a variation of Hybrid-Sharded Data Parallelism (HSDP) that further shards the optimizer state across intra- and inter-node data-parallel ranks, bridges the memory-communication trade-off between HSDP and FSDP, unlocking memory efficiency at minimal cost to performance.Hybrid-FSDP（HFSDP）是混合分片数据并行（HSDP）的一种变体，它把优化器状态进一步切分到节点内与节点间的所有数据并行 rank 上，在 HSDP 与 FSDP 之间搭起显存—通信的折中桥梁，以最小的性能代价换取显存效率。

ℹ️ Loading a fsdp_dtensor checkpoint raises an error if the checkpoint cannot supply every model weight the model asks for. Unlike torch_dist, the default --dist-ckpt-strictness assume_ok_unexpected behaves like raise_unexpected for this format, because Torch DCP skips absent weights silently and leaves them at their initialized values, which surfaces as a convergence regression rather than a crash. Weights that the checkpoint holds but a rank’s model does not ask for — sharded experts, for example — are always fine. Pass --dist-ckpt-strictness ignore_all to opt out, or --finetune when loading only part of the model is the intent.

FSDP FundamentalsFSDP 基本原理

Comparison between Distributed Data Parallelism (DDP) and Fully-Sharded Data Parallelism (FSDP). While gradients are all-reduced in DDP, they are sharded and reduce-scattered with FSDP.

上图为分布式数据并行（DDP）与全分片数据并行（FSDP）的对比：DDP 中梯度做的是 all-reduce，而 FSDP 中梯度被切分，做的是 reduce-scatter。

出处：Meta AI，Ott, Myle 等，《Fully Sharded Data Parallel: Faster AI Training with Fewer GPUs》，Facebook Engineering，2021-07-15。

Fully Sharded Data Parallelism (FSDP) is a type of distributed data parallelism (DDP) that shards optimizer state, weight gradients (wgrad), and model weights across devices that ingest data-parallel samples for data-parallel training or inference. Activations (fprop) and data gradients (dgrad) are not sharded or distributed, and are preserved for the backward pass, but can be recomputed during the backward pass, offloaded to CPU, or sharded / routed using other parallelisms such as tensor parallelism (TP), context parallelism (CP), or expert parallelism (EP).

全分片数据并行（FSDP）是分布式数据并行（DDP）的一种：它把优化器状态、权重梯度（wgrad）与模型权重切分到各个设备上，这些设备各自吃进数据并行样本，用于数据并行训练或推理。激活（fprop）与数据梯度（dgrad）不做分片或分发，而是为反向传播保留下来——但它们可以在反向传播时重算、卸载到 CPU，或用其它并行方式（张量并行 TP、上下文并行 CP、专家并行 EP）来切分/路由。

上图为 ZeRO 各阶段的显存剖面：ZeRO-1 切分优化器状态，ZeRO-2 切分优化器状态与梯度，ZeRO-3 切分优化器状态、梯度与参数。

The core principles of FSDP are:

FSDP 的核心原则有两条：

  1. Only a small depth-wise fraction of the model state can exist un-sharded at any point in time.在任意时刻，只有沿深度方向的一小部分模型状态可以处于未分片状态。
  2. Communication should overlap computation.通信应当与计算重叠。

From these core principles, software requirements can be derived:

由这两条原则可推导出若干软件要求：

  1. Model states sharded by FSDP are directly initialized across devices in shards.被 FSDP 切分的模型状态，直接以分片形式在各设备上初始化。
  2. Model parameters are all-gathered (AG) in pre-designated groups or modules pre-forward and pre-backward to un-shard a small fraction of the model state at any point in time during training or inference. After fprop and dgrad computation, the un-sharded weights are immediately de-allocated.在前向与反向之前，按预先指定的分组或模块对模型参数做 all-gather（AG），以便在训练或推理的任意时刻只临时解开一小部分模型状态。fprop 与 dgrad 计算完成后，这些已解开的权重立即释放。
  3. wgrad are reduce-scattered (RS) and accumulated in pre-designated groups or modules immediately post-backward to limit the amount of un-sharded gradients at any point in time during training or inference.反向传播一结束，权重梯度（wgrad）就在预先指定的分组或模块内做 reduce-scatter（RS）并累加，从而限制任意时刻未分片梯度的数量。
  4. Distributed optimizers, optimizers that are initialized with respect to a sharded model state and support distributed mechanics, update the sharded model state using the reduced gradient shard to implement data parallelism (DP).分布式优化器——即针对分片模型状态初始化、支持分布式机制的优化器——用归约后的梯度分片去更新分片的模型状态，从而实现数据并行（DP）。
  5. Computation and communication are overlapped across multiple CUDA streams, expending multiple streaming multi-processors (SM). Weights from subsequent groups or modules are pre-fetched, which ideally hides the communication latency required for FSDP behind model computation kernels (GEMM).计算与通信在多个 CUDA 流上重叠执行，占用多个流式多处理器（SM）。后续分组或模块的权重会被预取，理想情况下能把 FSDP 所需的通信延迟隐藏到模型计算内核（GEMM）背后。

FSDP can also be visualized as a decomposition of the all-reduce collective used in DDP into a gradient reduce-scatter, distributed optimization step, and parameter all-gather.

也可以换个角度看 FSDP：它把 DDP 里的那次 all-reduce 集合通信，拆解成了「梯度 reduce-scatter + 分布式优化步 + 参数 all-gather」三步。

出处：Feng, Wei、Will Constable、Yifan Mao，《Getting Started with Fully Sharded Data Parallel (FSDP2)》，PyTorch 教程，2022-03-17。

FSDP Unit Modules represent fractions of the model state that are computed and communicated as a (coalesced) group, un-sharded when needed for computation, and re-sharded after computation to release memory for subsequent model states. Implicitly, an FSDP unit module is also a modeling contract, requiring that FSDP-managed unit module parameters are not accessed or modified beyond the scope of the forward pass, backward pass, or optimization step.

FSDP 单元模块代表模型状态中的一部分：它们作为一个（合并的）整体参与计算与通信，需要计算时才解开分片，计算完立刻重新分片，把显存让给后续的模型状态。隐含地，FSDP 单元模块也是一条建模契约：不得在前向、反向或优化步的范围之外访问或修改由 FSDP 托管的单元模块参数。

Megatron-FSDP accepts a list of str or class paths representing FSDP unit modules via the fsdp_unit_modules argument, which is currently hard-coded to supported model classes (like TransformerLayer) in Megatron-Core. It performs a depth-first traversal of the model (via torch.nn.Module.named_modules()) and groups the parameters of each matching module for sharding and coalesced communication. Nested units are resolved by precedence: if a module matches an FSDP unit class but is already a sub-module of a previously registered FSDP unit, it is skipped, so the outermost (and necessarily largest) FSDP unit class in any module sub-tree becomes the effective FSDP unit module.

Megatron-FSDP 通过 fsdp_unit_modules 参数接收一组 str 或类路径，用以指定 FSDP 单元模块；目前该参数在 Megatron-Core 中被硬编码为受支持的模型类（如 TransformerLayer）。它会深度优先遍历模型（经由 torch.nn.Module.named_modules()），把每个匹配模块的参数归为一组，用于分片与合并通信。嵌套单元按优先级处理：若某个模块匹配 FSDP 单元类，但它已属于先前注册的某个 FSDP 单元的子模块，则跳过——因此在任一模块子树中，最外层（也必然最大）的 FSDP 单元类会成为实际生效的 FSDP 单元模块。

Double Buffering双缓冲

Megatron-FSDP uses a Tensor._typed_storage()._resize_(bytes)-based allocator to instantly allocate and de-allocate memory without depending on the CUDACachingAllocator for un-sharded parameters and gradients by default. (Cache fragmentation and garbage collection can procrastinate large quantities of cudaMalloc and cudaFree operations that can block programs and spike memory, particularly when memory utilization is maxed out.) However, modifying the underlying storage of a buffer is not compatible with NCCL symmetric registration or CUDA graphability, which require a persistent state during runtime.

默认情况下，对于未分片的参数与梯度，Megatron-FSDP 使用基于 Tensor._typed_storage()._resize_(bytes) 的分配器来即时分配与释放显存，不依赖 CUDACachingAllocator。（缓存碎片与垃圾回收会把大量 cudaMalloc / cudaFree 操作往后拖，这些操作可能阻塞程序、让显存占用突然冲高，在显存利用率接近上限时尤其明显。）然而，修改缓冲区的底层存储与 NCCL 对称注册、CUDA 图捕获都不兼容——这两者都要求在运行期保持持久状态。

To support these optimizations, Megatron-FSDP uses double-buffering, which assigns 2 persistently-allocated buffers to FSDP units in an alternating pattern, hard-limiting the memory overhead for parameter and gradient buffer allocation and ensuring that no more than 2 FSDP units are computed or communicated concurrently.

为支持上述优化，Megatron-FSDP 采用双缓冲：给 FSDP 单元交替分配两个持久分配的缓冲区，从而硬性限制参数与梯度缓冲区的显存开销，并确保同一时刻被计算或通信的 FSDP 单元不超过两个。

Visualization of double buffering in Megatron-FSDP. Even- and odd-indexed FSDP units share the same un-sharded parameter and gradient buffers, overwriting incumbent data as needed during runtime. Megatron-FSDP ensures that no more than two FSDP units are un-sharded at any point during runtime.

上图为 Megatron-FSDP 的双缓冲示意：偶数索引与奇数索引的 FSDP 单元共用同一对未分片参数/梯度缓冲区，运行时按需覆盖其中的旧数据。Megatron-FSDP 保证运行期间任意时刻解片的 FSDP 单元不超过两个。

With double-buffering, Megatron-FSDP does not need to allocate memory after initialization, which can reduce memory fragmentation and improve performance. However, double-buffering requires depth-wise model symmetry, where even- and odd-indexed FSDP units have identical size during runtime. If double-buffering is utilized, Megatron-FSDP computes the mode of FSDP unit sizes as the symmetrical double-buffer size, and any FSDP units not symmetrical to the computed size will default to the _resize_(bytes)-based allocator (or persistently allocated for extremely large and asymmetrical layers that affect performance significantly like torch.nn.Embedding when the low-level argument fsdp_db_use_persist_buf_on_alloc_fail is set).

有了双缓冲，Megatron-FSDP 在初始化之后就不再需要分配显存，这能减少显存碎片并提升性能。但双缓冲要求模型沿深度方向对称——即偶数索引与奇数索引的 FSDP 单元在运行时尺寸完全相同。若启用双缓冲，Megatron-FSDP 会取各 FSDP 单元尺寸的众数作为对称缓冲尺寸；与这个尺寸不对称的 FSDP 单元，默认回退到基于 _resize_(bytes) 的分配器；对于像 torch.nn.Embedding 这种极大且非对称、对性能影响显著的层，在设置了底层参数 fsdp_db_use_persist_buf_on_alloc_fail 时会改为持久分配。

Not all model architectures support depth-wise model symmetry. For example, hybrid architectures like Nemotron are a combination of Transformer, Mamba, and MoE blocks that are asymmetrical in size and data-type. To double-buffer these model architectures, we need a pool of buffers that can support any FSDP unit, which can be computed from the maximum of all FSDP units, and this “MaxPool” of (now symmetric) buffers of maximum size, shape, and dtype can be double-buffered.

并非所有模型架构都满足深度方向对称。例如 Nemotron 这类混合架构，由 Transformer、Mamba 与 MoE 块组合而成，在尺寸和数据类型上都不对称。要对这类架构做双缓冲，就需要一个能支撑任意 FSDP 单元的缓冲池——它可以由所有 FSDP 单元的最大值算出；这个「MaxPool」把缓冲区统一成最大尺寸、形状与 dtype（此时已对称），于是就能双缓冲了。

Visualizing the MaxPoolAllocator initialization in Megatron-FSDP. Iterating through all FSDP units, data buckets are categorized by data-type, sorted from small to large, and compared to the current MaxPool. If there are not enough buckets in the pool to support the unit, buckets are added to the pool (with size 0). If the largest buckets of the pool are not large enough to support the buckets in the unit (assigned to the pool from smallest to largest), the buckets in the pool are enlarged. After this process, we arrive at a minimal set of buckets that can double-buffer every FSDP unit in the model.

上图为 Megatron-FSDP 中 MaxPoolAllocator 的初始化过程：遍历所有 FSDP 单元，把数据桶按数据类型分类、由小到大排序，再与当前 MaxPool 比较。若池中桶数量不足以支撑该单元，就往池中补桶（尺寸为 0）；若池中最大的桶也不足以支撑该单元里的桶（由小到大分配到池），就把池中的桶扩大。这一过程结束后，就得到一组最小的桶集合，足以为模型中每个 FSDP 单元提供双缓冲。

Understanding Hybrid-FSDP (HFSDP)理解 Hybrid-FSDP（HFSDP）

Hybrid-FSDP (HFSDP) is a variation of HSDP where the optimizer state in particular is sharded across both DP-Inner and DP-Outer, i.e. all data-parallel ranks, which further reduces memory utilization. In other words, intra-node sharding and communication uses ZeRO-3, while inter-node sharding and communication uses ZeRO-1. Parameters and gradients are converted from and to the fully-sharded optimizer state during optimization steps only, reducing the frequency of inter-node communications.

Hybrid-FSDP（HFSDP）是 HSDP 的一种变体，其特别之处在于优化器状态同时在 DP-Inner 与 DP-Outer（即全部数据并行 rank）上切分，进一步降低显存占用。换句话说：节点内的分片与通信用 ZeRO-3，节点间的分片与通信用 ZeRO-1。参数与梯度只在优化步时与「全分片优化器状态」互相转换，从而减少节点间通信的频率。

Inspired by the artistry in the DHEN (Zhang, Luo, Liu, Meta, et al., 2022) paper.

本设计受 DHEN 论文（Zhang, Luo, Liu, Meta 等，2022）中巧思的启发。

Hybrid-Fully Sharded Data Parallelism (HFSDP) is a slight modification to HSDP that fully-shards the optimizer state across all data-parallel ranks and introduces outer-level all-gather and reduce-scatter collectives to map fully-sharded parameters and gradients into partially-sharded parameters and gradients.

Hybrid-Fully Sharded Data Parallelism（HFSDP）是对 HSDP 的小幅改造：把优化器状态在全部分数据并行 rank 上完全切分，并引入外层级的 all-gather 与 reduce-scatter 集合通信，把「全分片」的参数与梯度映射为「部分分片」的参数与梯度。

The memory profile of HFSDP is a “hybrid” of FSDP (optimizer state) and HSDP (gradients and model weights). Another elegant way to understand HFSDP functionality is ZeRO-1 composed with ZeRO-3.

HFSDP 的显存剖面是 FSDP（对优化器状态）与 HSDP（对梯度与模型权重）的「混合体」。理解 HFSDP 的另一种简洁视角是：ZeRO-1 与 ZeRO-3 的组合。

The modified algorithm has the following characteristics:

改造后的算法具有以下特征：

  1. Megatron-FSDP maintains a view of the model parameters sharded across all data-parallel ranks.Megatron-FSDP 维护一份在全部分数据并行 rank 上切分的模型参数视图。
  2. Distributed checkpoints save and load the fully-sharded model parameters.分布式检查点保存与加载的是全分片模型参数。
  3. Distributed optimizer state is initialized on the fully-sharded model parameters.分布式优化器状态在全分片模型参数上初始化。

During the first forward pass after checkpointing or optimization, fully-sharded model weights are all-gathered into partially-sharded model weights.

在检查点加载后或优化步之后的第一次前向传播中，全分片模型权重被 all-gather 成部分分片模型权重。

During the last backward pass before optimization, partially-sharded model gradients are reduce-scattered into fully-sharded model gradients.

在优化步之前的最后一次反向传播中，部分分片模型梯度被 reduce-scatter 成全分片模型梯度。

Otherwise, FSDP is performed on the partially-sharded model weights and accumulated gradients. Because model weights and gradients are only updated and ingested once per optimization cycle, we can skip or postpone all expensive inter-node / DP-outer collectives until an optimization step.

其余时间，FSDP 作用于部分分片的模型权重与已累加的梯度。由于模型权重与梯度在每个优化周期内只被更新和消费一次，那些昂贵的节点间 / DP-outer 集合通信就可以跳过或推迟到优化步再做。

In addition to improved memory utilization, HFSDP communications are split in communication size (bytes communicated), communication topology (DP-Inner and DP-Outer groups), and communication domain (NVLink and InfiniBand) across two sharding stages.

除了改善显存利用，HFSDP 还把通信按三个维度拆到两个分片阶段上：通信量（传输字节数）、通信拓扑（DP-Inner 与 DP-Outer 组）、通信域（NVLink 与 InfiniBand）。

Inter-node communications can also be parallelized with intra-node communications using separate CUDA streams.

借助各自独立的 CUDA 流，节点间通信也能与节点内通信并行执行。

Mixing FSDP & Model ParallelismFSDP 与模型并行的混用

Megatron-FSDP is also compatible with a variety of model parallelisms that shard the model state, such as Tensor Parallelism (TP) and Expert Parallelism (EP). When sharding model states across multiple dimensions in the device topology, FSDP sharding is always performed last, because FSDP collectives un-shard and re-shard parameters and gradients immediately before and after computation. Thus, FSDP sharding mechanics are implemented over tensor and expert parallel (strided) shards.

Megatron-FSDP 也兼容多种会切分模型状态的模型并行方式，例如张量并行（TP）与专家并行（EP）。在设备拓扑的多个维度上切分模型状态时，FSDP 的分片总是最后执行——因为 FSDP 的集合通信紧贴计算前后解开与重新分片参数、梯度。因此，FSDP 的分片机制是叠加在张量并行与专家并行的（跨步）分片之上实现的。

Megatron-FSDP uses torch.distributed.DeviceMesh to describe and configure communications across devices in data-parallel group(s). Because heterogeneous models that have mixed layers, such as Hybrid Mamba-Transformer or Mixture-of-Experts (MoE) models, require different parallelism configurations, multiple DeviceMesh(s) may be required for specific layers that require distinct distributed topologies for optimal memory efficiency and performance.

Megatron-FSDP 用 torch.distributed.DeviceMesh 来描述和配置数据并行组内跨设备的通信。由于层结构混合的异构模型（如 Mamba-Transformer 混合、MoE）需要不同的并行配置，某些层为了达到最优的显存效率与性能，可能需要各自专属的分布式拓扑，因此整体上可能需要多个 DeviceMesh。

Currently, Megatron-FSDP supports two DeviceMesh(s), one for dense / non-expert Module(s) and another for Megatron-Core MoE sparse / expert Module(s). (Expert modules and parameters in Megatron-Core are automatically detected.)

目前 Megatron-FSDP 支持两个 DeviceMesh：一个用于稠密/非专家模块，另一个用于 Megatron-Core 的 MoE 稀疏/专家模块。（Megatron-Core 中的专家模块与参数会被自动识别。）

  1. Dense modules typically have a DeviceMesh with data parallel, tensor parallel, and context parallel dimensions, where the data parallel dimension is used for FSDP. Typically, both data-parallel and context-parallel ranks are used for sharding in FSDP.稠密模块的 DeviceMesh 通常包含数据并行、张量并行与上下文并行三个维度，其中数据并行维度用于 FSDP。在 FSDP 中，通常数据并行与上下文并行的 rank 都参与分片。
  2. Mixture-of-experts modules typically have a DeviceMesh with data parallel, tensor parallel, and expert parallel dimensions, where the data parallel dimension is used for FSDP.MoE 模块的 DeviceMesh 通常包含数据并行、张量并行与专家并行三个维度，其中数据并行维度用于 FSDP。

For more information about Mixture-of-Experts in Megatron-Core, refer to the Megatron-Core User Guide - MoE.

关于 Megatron-Core 中 MoE 的更多信息，见《Megatron-Core 用户指南 - MoE》。

Non-Uniform / Un-Even Model Sharding非均匀/不等分模型分片

While torch.distributed.tensor.DTensor defaults to per-parameter sharding, where Tensors are split evenly on dim=0 across the data-parallel domain, Megatron-FSDP uses non-uniform or un-even DTensor shards of a (flattened) group of parameters associated with an FSDP unit.

torch.distributed.tensor.DTensor 默认采用「逐参数分片」，即把张量在 dim=0 上沿数据并行域均分；Megatron-FSDP 则不同：它把同一个 FSDP 单元关联的一组参数（展平后）做成非均匀/不等分的 DTensor 分片。

Comparison of FSDP2 per-parameter sharding and Megatron-FSDP per-unit or per-module sharding. FSDP2 requires COPY operations to move parameters and gradients in and out of communication buffers to reduce the frequency of NCCL collective calls, while Megatron-FSDP assigns sliced views of contiguous communication buffers to parameters associated with an FSDP unit.

上图为 FSDP2 的逐参数分片与 Megatron-FSDP 的逐单元（逐模块）分片对比：FSDP2 需要借助 COPY 操作把参数与梯度搬进搬出通信缓冲区，以降低 NCCL 集合通信的调用频次；Megatron-FSDP 则直接把连续通信缓冲区的切片视图分配给 FSDP 单元所关联的参数。

While complex and less user-intuitive, an un-evenly sharded data structure enables a few performance benefits without introducing expensive COPY operations to set up communication and computation buffers:

这种不等分的数据结构虽然更复杂、对用户也不够直观，但带来几项性能收益，且不必为搭建通信与计算缓冲区而引入昂贵的 COPY 操作：

  1. Fewer NCCL calls, reducing kernel launch and synchronization overhead. Only parameters in FSDP units that have different communication-related properties, such as their dtype or distributed topology, are coalesced into separate NCCL calls.NCCL 调用更少，降低内核启动与同步开销。只有那些通信相关属性（如 dtype 或分布式拓扑）不同的 FSDP 单元参数，才会被合并到不同的 NCCL 调用里。
  2. Flat communication and computation buffers are contiguous-by-design, supporting optimized CUDA kernels that require buffers backed by contiguous memory, such as grouped GEMMs used in MoE.扁平的通信与计算缓冲区天生连续，可支撑那些要求缓冲区底层连续内存的优化 CUDA 内核，例如 MoE 中使用的分组 GEMM。

Effectively, this implies that the same DTensor-sharded model parameters may have completely different shapes on different ranks, and if entire parameters are assigned to other ranks, the local Tensor will be empty.

实际后果是：同一批经 DTensor 分片的模型参数，在不同 rank 上可能有完全不同的形状；如果某个参数整体被分给了别的 rank，本地的 Tensor 就会是空的。

说明Megatron-FSDP 提供了一个顺手的库（megatron_fsdp.uneven_dtensor）来操作不等分分片的 DTensor，聚焦于逐参数操作，例如解开分片，或归约那些在不同 rank 上形状不同的参数。需要注意：参数组本身对 FSDP 集合通信是均分的，但逐参数集合通信（默认假设设备之间传输对称的字节数）在遇到不等分 DTensor 时，会一直等待那些永远不会到达的字节而挂死。

In particular, contiguous memory is only half the requirement for high-performance CUDA kernels. The other requirement is locality, which FSDP can violate, that introduces compatibility issues when combining FSDP with present and future optimizations. For example, block-wise quantization (scaling factor / absmax calculations for MXFP8, NVFP4, etc.) requires DP communication and custom max-reduce kernels if the block is sharded by FSDP.

尤其要注意：连续内存只是高性能 CUDA 内核所需条件的一半，另一半是局部性（locality）——而 FSDP 可能破坏它，这会在 FSDP 与现有及未来的优化手段结合时引发兼容性问题。举例来说，分块量化（为 MXFP8、NVFP4 等计算缩放因子/absmax）若其块被 FSDP 切分，就需要数据并行通信以及自定义的 max-reduce 内核。

Megatron-FSDP supports dim=0 sharding, which computes the least-common multiple (LCM) of p.shape[1:] for all parameters p in an FSDP unit and pads the un-sharded buffer to the closest multiple of DP x LCM(p.shape[1:]), forming a “DP-LCM” partition with LCM-length parts to ensure that DP-sharding boundaries do not violate chunks of data for coordinates of dim=0.

Megatron-FSDP 支持 dim=0 分片：先对一个 FSDP 单元内所有参数 p 求 p.shape[1:] 的最小公倍数（LCM），再把未分片缓冲区的尺寸补齐到 DP × LCM(p.shape[1:]) 的最近整数倍，从而形成以 LCM 长度为一个分区的「DP-LCM」划分。这样能保证 DP 分片的边界不会切断 dim=0 各坐标上的数据块。

Visualization of how parameters are assigned un-evenly to the flat per-unit buffer sharded across DP ranks. With the LCM algorithm, every slice of dim=0 is never bisected by FSDP. Algorithms and compute kernels can leverage this locality and contiguity.

上图为参数如何被不等分地分配进「跨 DP rank 分片的扁平逐单元缓冲区」。借助 LCM 算法，dim=0 上的每一个切片都不会被 FSDP 从中间切开，算法与计算内核因而可以利用这种局部性与连续性。

  1. When a parameter is divisble by the LCM, it can be inserted at any index multiple of the LCM in the buffer that is free. p[i] chunks of this parameter by definition divide the LCM, and thus align with the DP-LCM sharding grid.若参数尺寸能被 LCM 整除，就可以把它插入缓冲区中任意空闲的、下标为 LCM 倍数的位置。该参数的 p[i] 块按定义能整除 LCM，因而与 DP-LCM 分片网格对齐。
  2. When a parameter is larger than but not divisible by the LCM, the remainder r populates a fraction of another LCM part, so a “conjugate” parameter that also exceeds the LCM with a “conjugate” remainder r' that is less than or equal to LCM - r is installed to fill the remaining space and align with the DP-LCM sharding grid.若参数尺寸大于 LCM 但不能整除它，余数 r 会占掉另一个 LCM 分区的一部分空间；这时会安装一个「共轭」参数——它同样超过 LCM，且其余数 r' 满足 r' ≤ LCM − r——用来填满剩余空间并与 DP-LCM 分片网格对齐。
  3. When a parameter is smaller than but not divisible by the LCM, a post-assignment sweep on the leftover space in the flat buffer is run, and all gaps that are multiples of the LCM that are large enough to support the entire parameter are utilized. Once all gaps are filled, the final parameters are assigned to the tail of the buffer respecting the DP-LCM sharding grid.若参数小于 LCM 且不能整除它，会对扁平缓冲区中的剩余空间做一次「事后扫描」，把所有长度是 LCM 的整数倍、且足以完整容纳该参数的空隙都利用起来。空隙用尽后，剩余参数被分配到缓冲区尾部，同时遵守 DP-LCM 分片网格。
说明Megatron-FSDP 对连续性与局部性的通用支持仍在开发中，将随开源社区与 PyTorch 的贡献演进。关于内核缓冲区需求如何影响 FSDP 数据结构设计，可参阅 veScale 论文（Li, Youjie，ByteDance Seed 等，《veScale: Consistent and Efficient Tensor Programming with Eager-Mode SPMD》），其中对这些需求做了全面分析。

Quantization量化

Quantization is an extremely important feature for Megatron-FSDP as it reduces memory utilization and communication size for both activations and parameters, which directly affects the viability and performance of FSDP.

量化对 Megatron-FSDP 极为重要：它能同时降低激活与参数的显存占用和通信数据量，而这两者直接决定 FSDP 是否可行、性能如何。

Visualization of Megatron-FSDP’s training loop when using quantized weights from TransformerEngine. Every optimization step updates the quantized representation of sharded model weights, which have reduced communication size.

上图为 Megatron-FSDP 在使用 TransformerEngine 量化权重时的训练循环：每个优化步都会更新分片模型权重的量化表示，后者的通信数据量更小。

While TransformerEngine handles activation quantization, Megatron-FSDP shards quantized weights for AG.

  4. Sharded Quantization - Sharded main weights are quantized to update the quantized compute weights for subsequent training steps.分片量化——对分片的主权重做量化，以更新量化计算权重，供后续训练步使用。

Sharded quantization involves reducing maxima to compute a global set of scaling factors for local / sharded quantization.

分片量化的做法是：先归约各处的极大值，算出一套全局缩放因子，再据此做本地/分片量化。

In particular, sharded quantization minimizes communication size and memory utilization by communicating scaling factors instead of main weights.

具体而言，分片量化通过传输「缩放因子」而不是「主权重」来最小化通信量与显存占用。

  2. Global Abs-Max - Globally all-reduce maxima and derive scaling factors from maxima.全局 Abs-Max——在全局范围 all-reduce 各极大值，并由极大值推导缩放因子。
  3. Local Quantization - Locally quantize sharded main weights and install into compute weight buffers.本地量化——在本地对分片主权重做量化，并装入计算权重缓冲区。

Mixed-Precision混合精度

Megatron-FSDP sharding and communication buffers support mixed-precision, such that users can customize the dtype used for main weights, gradient communication (reduction), and gradient accumulation in addition to the native or quantized dtype used for model computation. These options are wrapped in a MixedPrecisionPolicy dataclass.

Megatron-FSDP 的分片与通信缓冲区支持混合精度：除了模型计算所用的原生或量化 dtype 之外，用户还能自定义主权重、梯度通信（归约）以及梯度累加所使用的 dtype。这些选项封装在 MixedPrecisionPolicy 数据类里。

  1. Main Weight Precision - Controls the data-type for parameters responsible for distributed optimization, distributed checkpointing, and quantization. If set to auto (None), the native model compute parameter data-type will be utilized. Required for parameter quantization with --fp8-param-gather. Defaults to torch.float32.主权重精度——控制用于分布式优化、分布式检查点与量化的参数数据类型。若设为 auto（None），则采用模型原生的计算参数类型。配合 --fp8-param-gather 做参数量化时必需。默认 torch.float32。
  2. Main Gradient Precision - Controls the data-type for wgrad accumulation and distributed optimization. Defaults to auto (None), the model native gradient data-type will be utilized. While torch.float32 (or higher) is recommended for accuracy at scale, as main_grads_dtype controls the data-type for gradient accumulation, auto is more flexible and uses pre-determined parameter gradient logic in mixed-precision scenarios, such as BF16 for FP8/FP4 parameters quantized via TransformerEngine.主梯度精度——控制 wgrad 累加与分布式优化所用的数据类型。默认 auto（None），即采用模型原生梯度类型。虽然在大规模下为精度起见推荐 torch.float32（或更高），但由于 main_grads_dtype 直接决定梯度累加的类型，auto 更灵活：它会沿用混合精度场景下既定的参数梯度逻辑，例如对经 TransformerEngine 量化的 FP8/FP4 参数使用 BF16。
  3. Gradient Communication Precision - Controls the data-type for gradient communications when reducing gradients. Lower precision improves (communication) performance. Defaults to auto (None), in which the main gradient data-type will be utilized. If using no_shard, optim, HSDP, or HFSDP, allocating dtype-custom gradient communication buffers may increase per-unit memory overhead, so users should consider the performance-memory trade-off when using this feature.梯度通信精度——控制归约梯度时通信所用的数据类型。精度越低，通信性能越好。默认 auto（None），此时采用主梯度的数据类型。若使用 no_shard、optim、HSDP 或 HFSDP，分配自定义 dtype 的梯度通信缓冲区可能增加每单元的显存开销，启用该特性时需权衡性能与显存。

If using NCCL symmetric registration v2.27+, gradient reduction may be performed in high-precision depending on the network domain (NVLink or IB), and can enable mixed-precision communication and accumulation, e.g. setting grad_comm_dtype to BF16 can support FP32 reduction even though we have BF16 input and output communication buffers. Otherwise, gradients will be reduced and accumulated in communication and accumulation precision as usual.

若使用 NCCL 对称注册 v2.27+，梯度归约可以按网络域（NVLink 或 IB）以高精度执行，并支持混合精度的通信与累加——例如把 grad_comm_dtype 设为 BF16 时，即使通信缓冲区的输入输出都是 BF16，仍可支持 FP32 归约。若不满足该条件，梯度就按通信精度与累加精度照常归约与累加。

NVIDIA Collective Communications Library (NCCL) implements multi-device and multi-node communication primitives optimized for CUDA devices and networking from NVIDIA. Megatron-FSDP communications are registered and deeply integrated with NCCL, which enables a variety of hardware-level networking optimizations such as copy-engine AG, high-precision RS, SHARP reduction offloading, and symmetric kernels.

NVIDIA 集合通信库（NCCL）实现了面向 NVIDIA CUDA 设备与网络优化的多设备、多节点通信原语。Megatron-FSDP 的通信被注册进 NCCL 并与之深度集成，从而可用上多种硬件级网络优化，例如 copy-engine all-gather、高精度 reduce-scatter、SHARP 归约卸载与对称内核。

To leverage NCCL networking optimizations, NCCL user buffer registration (UBR) is required to inform NCCL of PyTorch Tensors (“user buffers”) that act directly as the input and target of NCCL collectives for PyTorch ProcessGroup(s). Because registered communication buffers are known to NCCL, COPY operations that send collective inputs to NCCL buffers and collective outputs to PyTorch buffers are no longer required, which enables Megatron-FSDP to be zero-COPY end-to-end.

要用上 NCCL 的网络优化，必须先做 NCCL 用户缓冲区注册（UBR）：把直接充当 PyTorch ProcessGroup 集合通信输入与目标的 PyTorch Tensor（即「用户缓冲区」）告知 NCCL。既然这些通信缓冲区已在 NCCL 处登记，就不必再用 COPY 操作把集合通信的输入搬进 NCCL 缓冲区、再把输出搬回 PyTorch 缓冲区——Megatron-FSDP 因此得以端到端零拷贝。

NCCL (v2.27+) supports symmetric allocation or registration for communicators over the NVLink domain, which allow buffers that share identical virtual addresses across devices to benefit from optimized collectives:

NCCL（v2.27+）支持在 NVLink 域上对通信器做对称分配或对称注册，使得在各设备上共享相同虚拟地址的缓冲区能享受优化过的集合通信：

  1. Symmetric Kernels - On the NVLink domain, symmetric kernels operating on symmetric memory reduces the SM utilization for a single communication kernel to 1.对称内核——在 NVLink 域上，作用于对称内存的对称内核能把单次通信内核的 SM 占用降到 1。
  2. NVSwitch SHARP Offloading - To further minimize SM utilization for AG and RS collectives, NCCL SHARP offloads reduction and aggregation work to NVLink and IB Switch hardware that uses 1-6 SM depending on the domain: NVL, IB, or NVL + IB.NVSwitch SHARP 卸载——为进一步压低 AG 与 RS 集合通信的 SM 占用，NCCL SHARP 把归约与聚合工作卸载到 NVLink 与 IB 交换机硬件上，按域不同（NVL、IB 或 NVL + IB）占用 1–6 个 SM。
  3. Copy-Engine (CE) Collectives: Instead of using SMs (or CTAs) for common non-computational collectives like AG in Megatron-FSDP, copy engines are instead used to perform all-gather collectives, dedicating SM resources to compute and reduction during FSDP. Requires NCCL v2.28+.Copy-Engine（CE）集合通信：在 Megatron-FSDP 中，像 all-gather 这类常见的非计算型集合通信不再占用 SM（或 CTA），而是交给拷贝引擎（copy engine）执行，从而在 FSDP 期间把 SM 资源专门留给计算与归约。需要 NCCL v2.28+。
  4. High-Precision Reduction: When training large models, high-precision gradient reduction and accumulation is desired for accuracy and convergence, but communicating FP32 gradients is expensive. With symmetric registration, FP32 accumulators enable gradients to be reduced in FP32 but communicated in BF16, which decreases gradient RS communication latency while maintaining high accuracy during training. Megatron-FSDP supports FP32 main gradient accumulation but BF16 gradient communication, customizable through megatron_fsdp.MixedPrecisionPolicy.高精度归约：训练大模型时，为精度与收敛着想希望梯度归约与累加都保持高精度，但直接传输 FP32 梯度代价很高。借助对称注册，FP32 累加器可以让梯度「以 FP32 归约、以 BF16 传输」，既降低梯度 RS 的通信延迟，又保住训练精度。Megatron-FSDP 支持 FP32 主梯度累加 + BF16 梯度通信，可通过 megatron_fsdp.MixedPrecisionPolicy 自定义。

These optimizations significantly reduce SM resource contention for overlapped compute and communication kernels in FSDP. Symmetric registration, allocation, and pooling is also supported in PyTorch: torch.distributed._symmetric_memory.

这些优化显著缓解了 FSDP 中计算内核与通信内核重叠执行时的 SM 资源争用。PyTorch 同样支持对称注册、对称分配与对称池化：torch.distributed._symmetric_memory。
