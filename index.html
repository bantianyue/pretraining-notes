机器学习系统（规模化）：分布式训练

原文：Machine Learning Systems at Scale — Distributed Training（MLSys Book Vol.2）｜ 中文精读已完成

核心思想：分布式训练是约束满足问题，不是硬件乘法。单步时间 T_step(N) = T_compute/N + T_comm(N) + T_sync(N) − T_overlap，通信-计算比 ρ 决定集群是超算还是一堆闲置电暖器。DP = 并行 for 循环（按 batch 展开），TP = 向量化/SIMD（按矩阵乘内层展开，NVLink 当向量寄存器），PP = 指令流水线（按 layer 分段）。

  • DP：每卡完整模型副本 + 数据分片，AllReduce 同步梯度。纯 DP 在 1024 卡上效率只有约 37.5%。三堵墙：显存墙、带宽墙、batch 陷阱（critical batch size）。
  • ZeRO / FSDP：分片式 DP。ZeRO-1 切优化器状态，ZeRO-2 加切梯度（ReduceScatter 代替 AllReduce），ZeRO-3/FSDP 再切参数（每层前向 AllGather 即时重建）。7B 模型 64 卡可把每卡状态从 112GB 压到 1.75GB，代价是 10–25% 通信开销。注意：ZeRO 切不动 activation，长上下文还得靠模型并行。
  • PP：按层切 stage，stage 间只传 activation（B_μ×S×d_model×2 字节），可走 InfiniBand 跨节点。bubble = (p−1)/(m+p−1)，p=8/m=32 时约 18%。调度演进：GPipe → 1F1B（activation 峰值从 O(m×p) 降到 O(p)，才能堆 m≫p 压 bubble）→ zero-bubble（拆 B/W 核填空闲）。
  • TP：Megatron 列并行+行并行配对，每 block 只需 2 次 AllReduce。只能待在 NVLink 节点内（跨节点 MFU 跌到个位数），一般不超过 8 路。
  • CP（训练侧）：Ring Attention 沿序列切分，K/V 块在环上轮转，N 卡把上下文放大 N 倍——和推理 decode CP 同一思想。
  • EP（MoE）：All-to-All dispatch/combine 路由 token；capacity factor（1.25–1.5）+ auxiliary load balancing loss 对付路由偏斜。
  • 混合 3D：N = d×p×t。TP-8（NVLink 节点内）+ PP-4（邻近节点）+ DP-32（全集群），DP 只同步 1/32 参数分片——这就是 TorchTitan 的 FSDP+TP+PP+CP 4D 并行的理论底座。选型原则叫 hierarchy-aware parallelism：把通信画到带宽地形上，高频小消息走 NVLink，量大低频的走全集群。

并行策略（推理）

vLLM 上下文并行部署

原文：Context Parallel Deployment — vLLM（官方文档）｜ 中文精读已完成
  • Prefill CP：长请求切 N 个 chunk，每卡算一个 chunk 的 Q/K/V。两种模式：部分 query + 全量 K/V（加速 prefill，控 TTFT）；部分 query + 部分 K/V（放不下全量 K/V 时，用 ring-attention 逐块传）。
  • Decode CP：核心是沿 T 维度切分 KV cache。TP 先沿 H 维度切，但 H 有限，TP 放大后每卡 KV cache 被复制 tp_size/H 次；加 -dcp 沿序列维度继续切，消除复制。-dcp 不增加 GPU 数，取值范围 [1, tp_size/H]，越大复制越少、通信越多。KV cache 增长用交错（interleaving）策略切分。
  • 实战：DeepSeek-R1（MLA，1 个 kv-head）-tp 8 有 8 倍复制，加 -dcp 8 消除；Kimi-K2 -tp 16 用 -dcp 16 全消或 -dcp 8 降到 2 倍（节点内通信开销小）；Qwen3-235B-A22B（4 个 kv-head）-tp 8 配 -dcp 2。经验法则：先把 tp 加到性能满意，再加 dcp 消复制。
  • 与训练 CP 对照：同一思想（沿 sequence 切），目标不同——训练要吞吐+显存，推理要延迟+KV cache 利用率。

推理可观测

vLLM 生产环境监控指标

原文：Production Metrics — vLLM（官方文档）｜ 中文精读已完成

/metrics 端点（Prometheus 格式）。排障速查：

  • TTFT 高 → request_prefill_time_seconds + kv_cache_usage_perc（cache 满会导致 prefill 排队）；
  • decode 慢 → request_decode_time_seconds + time_per_output_token_seconds；
  • 排队久 → num_requests_waiting_by_reason 区分容量问题还是 LoRA/KV 约束；
  • 吞吐上不去但卡不忙 → iteration_tokens_total（batch 没打满）+ num_preemptions（频繁抢占说明 KV 压力大）。
  • 另有前缀缓存命中率、推测解码接受率、MFU 估算（FLOPs/访存量，需 --enable-mfu-metrics）、NIXL/CPU-offload 的 KV 传输指标。

Kernel 优化

Modular：LLM 推理的 Kernel 优化

原文：Kernel Optimization — LLM Inference Handbook（Modular）｜ 中文精读已完成（覆盖 3 个子页面）
  • 分层：kernel 优化回答"单个算子在 GPU 上跑多快"，系统优化（batching/caching/routing）回答"请求在 serving 架构里流得多顺"。kernel 层是上面一切的天花板。
  • 核融合：y = silu(h + bias) * scale 不融合要 3 次 launch、6 次 HBM 往返，融合后 1 次 launch、2 次往返——融合的本质是减少 HBM round-trip。
  • 工具阶梯（控制力↑、门槛↑、可移植性↓）：cuBLAS/cuDNN → TVM/XLA（auto-tuning）→ Triton（tile 模型）→ 手写 CUDA → Mojo/MAX（MLIR 一栈多后端，写一次跑 NVIDIA/AMD）。选型：标准算子用 vendor 库，图级消往返用编译器，自定义 kernel 用 Triton，要控制+可移植看 Mojo/MAX，榨干特定硬件才手写 CUDA。
  • FlashAttention：tiling + 重算 + 融合，N×N attention 矩阵永不在 HBM 物化，快 2–4 倍。FA-1（2022）→ FA-2（warp 并行）→ FA-3（Hopper，H100 740 TFLOPS）→ FA-4（2026，Blackwell 定制，B200 1613 TFLOPS/s）。FA 同时是训练侧核心 kernel，缓解训练 attention 显存墙。
